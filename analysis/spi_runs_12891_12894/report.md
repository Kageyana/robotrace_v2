# SPI 5.625 MHz変更後の走行ログ

ユーザー確認により12891～12894の4本すべてがSPI変更後。いずれもIMU積算角度の符号はCW。4本とも正常終了、期待行数一致、IMU校正100サンプル・読出しエラー0、距離換算検証成功。3軸加速度・角速度・温度・角度は有限値、温度無効値なし。走行中SPIエラー数や割り込み処理時間の測定値はログにないため、1ms期限・全読出し成功を直接確認したわけではない。

## 周回ずれと速度

ライン素子8個の通過距離をCAD位置で補正した独立CROSSを使い、6回の通過間の5周を比較した。距離は左右積算パルス平均、方位は1ms積算imuAngle_Z、区間中点方位で位置積分。CSVのx/yを真値としていない。

変更前のCW12885～12888・12890は目標0.5 m/s、エンコーダ平均0.534～0.546 m/s、平均Xずれ+7.79 mm/周、平均閉路誤差8.55 mm/周。変更後の目標0.5 m/sの2本は平均Xずれ-3.76 mm/周、平均閉路誤差7.13 mm/周。以前の一貫したX＋方向のドリフトは今回4本では見られないが、負方向のドリフトやYずれは残っている。

**平均走行速度が低下し、電圧も変更前7.52～7.77 Vから変更後7.42～7.49 Vへ変わっている。SPIだけの効果とは断定できない。** 目標1.0 m/sの2本には同条件の変更前比較がない。実際の移動距離・方位は外部計測していない。

## ログ取得

目標0.5 m/sのログの最大時刻間隔は22ms、1.0 m/sでは7ms。これは5mm距離基準ログであり、取得周期そのものではない。全4ログの隣接距離間隔は4.21～5.75mmで、速度低下時も距離基準で記録されている。22msだけを理由に欠落や制御周期超過と判定しない。

温度は校正・走行時とも有効で、3軸値の更新も確認できる。一方、HAL_SPIの走行中成否とIMUデータレディ時刻は未記録。初期化後レジスタ読戻しもない。残っているリセット待機不足などの問題がなくなったとは判断しない。

12891・12892のヘッダbuildTimeは18:22:31、12893・12894は21:25:34。buildTimeはSDcard.c側のコンパイル時刻であり、main.cのみ再ビルドしてSPI分周を変えた場合に古い時刻が残り得る。ユーザー確認を優先し、時刻だけで変更前と分類しない。
