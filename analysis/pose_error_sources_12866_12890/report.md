# IMU方位・左右距離換算・取得タイミングの切り分け

機体中心の横滑りを無視する前提で正常終了11ログを解析した。**固定した左右換算差と数msの一定取得時刻差は、現在のX＋方向への周回ずれの主因としては影響が小さい。IMU方位誤差は12888で独立ライン検出にも現れるが、一定バイアスや倍率だけではXずれを解消しない。主因の確定には至っていない。**

## 対象と検証

- CW12866～12868、CCW12869～12871、CW12885～12888・12890。全ログの目標速度は約0.5 m/s、1次走行、正常終了、IMU校正・距離換算検証成功、期待行数一致、時刻単調増加、最大記録間隔11 ms以下。
- 12889はemcStop=3で除外。
- 電圧は旧組8.06～8.30 V、新組7.52～7.77 V、温度・ビルド時刻も異なるので、両組のドリフト量の違いを特定の変更の効果とは判断しない。
- raw左右積算値から距離、1 ms積算imuAngle_Zから方位を再計算。疎なgyroVal_Zは再積分しない。
- マーカーGPIO確定時刻を使わず、全幅ライン検出とCADの8素子位置から車軸中央のCROSS通過位置・相対姿勢を推定。1走の6回通過の間にある5周を比較。
- 入力SHA256と解析後の一致を確認。元CSV、ファームウェア、ビューワーは変更していない。

|組|方向|Xずれ平均 [mm/周]|IMU旋回角度の±360°からの差 [deg/周]|独立ライン姿勢変化も差し引いた角度残差 [deg/周]|
|---|---|---:|---:|---:|
|12866～12868|CW|+16.62|+0.086|+0.152|
|12869～12871|CCW|+14.33|+0.076|+0.100|
|12885～12888・12890|CW|+7.79|-0.016|-0.012|

組平均の角度誤差が小さくても、各走の正負の誤差が相殺される。IMUが正しいことの証明にはならない。

## 1. 左右の距離換算差

方位をIMUのまま保持し、左距離を0.995倍、右距離を1.005倍（左右相対差1%）にする場合と、逆の場合を比較した。距離換算差からエンコーダ方位を推定する実験ではなく、現行の平均距離＋IMU方位方式への影響を調べた。

|組|相対差1%による閉路位置変化のRMS [mm/周]|
|---|---:|
|旧CW|0.027|
|旧CCW|0.031|
|新CW|0.024|

2%までの探索でも閉路RMSの改善は最大約0.06 mm/周。一定左右換算差だけではXずれを説明できない。左右共通の距離換算を1%変更すると軌跡全体の大きさが1%変化し、既存閉路ずれも約1%変化するだけで、閉路へ戻す補正にはならない。

理由：補正距離の差は左右輪の距離差に比例する。一定の有効トレッドで左右輪差が旋回角度に比例する場合、完全な1周ではこの項が位置積分で相殺される。左右換算差はエンコーダから方位を計算する方式では重大になり得るが、今回のIMU方位方式とは影響が異なる。

encTotalOptimalとraw左右積算平均の相対値の差は全11ログで±0.5 pulse以内（0.00862 mm以内）。平均の半パルス端数の持ち越しと整合し、距離積算の周期ずれ・途中リセット・長期切り捨ての証拠はない。制御コードのSLIP_DIST_CORRECTION_ENABLEは0。

各周の輪差÷IMU旋回角度からの有効トレッドは旧CW112.47 mm、旧CCW112.24 mm、新CW113.53 mm。これは横スクラブ・接触点・左右換算・IMU誤差を含む診断値で、実寸や左右タイヤ倍率として採用しない。

## 2. 距離と角度のタイミング

記録時刻に対して方位だけを±1、±5、±10 msずらし、補間して位置積分を比較した。正値は後のIMU方位を使う。

|組|±1 msの位置変化RMS [mm/周]|±10 msの位置変化RMS [mm/周]|
|---|---:|---:|
|旧CW|0.040～0.056|0.268～0.285|
|旧CCW|0.074～0.121|0.906～0.944|
|新CW|0.063～0.070|0.527～0.541|

10 msの一定ずれでも残る7～17 mm/周のXずれより小さい。20 msまでの閉路合わせ探索も解消しない。旧CWは負側、新旧CW・CCWで最適符号や改善量が異なり、閉路最小値からセンサー遅延を同定しない。

区間中点方位を左端または右端方位へ変更した場合も、閉路位置変化は約0.10～0.11 mm/周。単純な積分端点選択は主因ではない。

### 現行コードの確認

- `timer.c:30`のInterrupt1msで、cntRun更新 → getEncoder → setEncoderVal → BMI088getGyro → calcDegrees → writeLogBufferPutsの順。
- `IMU.c:148`でZ角度を補正済みgyro.z×DEFF_TIME（0.001 s）により積算。
- `SDcard.c:779`のwriteLogBufferPutsでスキーマの時刻・距離・IMU角度を同じ割り込み内でバッファ化。CSV生成はその記録済み累積値を使用。
- TIM6は優先度0、TIM7ログ転送要求は優先度10。TIM7による次周期のエンコーダ/IMU更新混入はない。
- BMI088のジャイロ設定はコード上ODR1 kHz・帯域116 Hz。データレディ同期やセンサー固有の取得時刻はログにない。エンコーダは1 ms区間カウント、角速度は内部フィルタ付きサンプルなので、実効遅延は未測定。
- 実行周期のジッタ、SPI読出し失敗時の古い値の再使用、動的な遅延は現在CSVから断定できない。走行中のBMI088getGyro戻り値はタイマー側でチェックしておらず、校正時の読出しエラー0とは別に扱う必要がある。

これは「全種類のタイミング異常を除外した」という結論ではなく、一定の数msずれとロガーの別周期混入の可能性を限定した結果。

## 3. IMU方位誤差

全走に一定角速度バイアス±0.3 deg/s、角度倍率±0.5%をそれぞれ追加し感度を確認。閉路RMSを最小にする値は走行ごとに変わり、最小にしても閉路が残る。閉路合わせ最適値は校正値ではない。

独立CROSS姿勢も利用した検証では、ライン素子ごとの通過距離をCAD前後位置で補正し、横位置xに対する通過距離の傾きから実姿勢の変化を推定した。初期方位やCROSSの世界座標方向の未知定数は周回差で相殺する。ライン形状・閾値・光学実効位置による誤差は残る。

### 12888の具体例

IMU旋回角度は360°より平均0.343°/周少ない。実際のCROSS姿勢変化も差し引くと不足は0.317°/周。閾値800～1500の変更でも不足0.289～0.409°/周であり、方向は変わらない。

この不足が一定バイアスだけで生じたと仮定し、+0.03685 deg/sを追加すると：

|指標|元|ライン拘束による一定バイアス補正|
|---|---:|---:|
|Xずれ [mm/周]|+6.32|+5.32|
|閉路誤差RMS [mm/周]|6.83|6.29|

一定倍率の仮説なら+0.08824%でXずれ+5.67 mm/周。どちらも解消しない。既存温度補正やジャイロ係数の採用変更はしていない。他走では同じ種類の拘束補正で改善するものと悪化するものがある。

## 切り分け結果と残る項目

1. 一定左右換算差・半パルス丸め：主因としての優先度を下げられる。曲率・荷重・速度依存で変わる距離誤差は未除外。
2. 同じレコードの距離・角度の取り違え、一定数msのずれ、積分端点：主因としての優先度を下げられる。内部フィルタ、読出し失敗、周期ジッタは未測定。
3. 一定IMUバイアス・倍率：一部の誤差に寄与するが、残るX＋ドリフトの主要部分は説明できない。周回途中に現れ、終点では相殺される方位誤差は未除外。

**現在のログには周回途中の実方位と実移動距離の独立観測がないため、区間依存のIMU誤差と区間依存の距離誤差を一意に分離できない。** 次の独立検証は、第二コーナーの動画で車輪の回転量だけでなく機体の床に対する方位・中心移動を追跡し、ログとの時刻対応と撮影倍率・遠近を確認して比較すること。既存動画はスロー再生で、現時点では厳密な時間対応・床上のスケールが確定していない。

実機側でタイミングの未確定項目を測る場合は、制御周期の実測、IMU読出し成功/失敗数、データレディに対する読出し時刻が必要。未確定な係数補正を先に採用する根拠はない。
