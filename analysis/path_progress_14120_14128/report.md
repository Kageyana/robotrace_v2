# 初回の前後補正診断：14120〜14128

SD診断の保存は確認できたが、診断を持つ6走とも前後補正の受理0回・実適用0mmだった。今回の実走では新しい前後補正が働いておらず、距離補正によるコースアウト改善を確認したとは扱わない。

最新14128は一次14126参照のPATH_CURVE。ユーザーは白線を外れて停止したと確認した。最後の記録は3.109秒・車輪距離9.113m、emcStop=7。記録末尾が停止判定の1msと一致するとは限らない。

## 記録形式の確認

- 14128は制御版30・補正版1、ビルド15:16:43、通常67列。前後補正12列が全行にあり、slip診断9列はない。
- 一次14126は通常65列で、slip列を含む従来の一次形式を維持している。
- 14128の1821行を含め、8 CSVの全行幅・有限性・期待行数・時刻単調性・変換番号を確認した。前後補正の区間和、累積列、ヘッダの実適用量と受理件数も一致した。
- 14128の記録間隔は最大5ms、車輪距離間隔は最大9.678mm。距離記録のため、1ms連続でないことや高速時に5mmを超えることだけで欠落とはしない。制御周期の実時間余裕・センサー取得鮮度は本ログから未確認。
- 8原本の解析開始・終了SHA256は不変。原本binの全CRCは今回照合していない。

14128の数値評価で記録された情報量は最大0.029575、採用下限0.08を下回る。8回の数値更新はすべて識別不能の記録で、横位置・方位を分離した前後位置を一意に定められていない。最後の数値更新は2.455秒・7.467m、RMS1.549mm・情報量0.027117。終了時は更新後654ms経過しており、末尾の数値は逸脱直前に成立した推定ではない。

`pathProgressAlong_mm=±30mm/0mm`が多いが、これは3候補の初期値と一致する。識別性検査で反復更新前に棄却された候補であり、実際に30mmずれていたと解釈しない。

14122では空間照合が通った保存行が1行、14123では2行あるが、別時点の連続一致を満たして受理するところまで至っていない。したがって情報量の閾値だけを下げれば解決すると断定できない。

## 履歴を維持できない要因

現行コードは滑りフラグが1つでもONなら新補正を無効にし、履歴と補正先を破棄する。直前のslip列ありログ14121では、TRACKING/CAUTION中にReason=0だった3103記録のうち2856記録（約92%）で滑りフラグがONだった。14123は3336中2908、14125は870中820だった。複数条件が同時成立する場合もあるため、滑りだけに原因を限定しない。

14128のReason=0は、設定・滑り・保護域・対応失敗・退避等をまとめた状態である。slip列を外したため、14128の無効化を滑りの軸まで分解することはできない。過去ログの傾向を14128の1ms原因へそのまま代入しない。

実走で連続した履歴を確保できる条件と、実コースの形状から前後位置を識別できる条件の両方を再検討する必要がある。安全上の保留条件を単に外したり、候補の初期値を距離補正に使ったりしない。
