# ログ解析の再発防止

対象CSVを数値計算へ渡す前に以下を確認する。原本を変更せず、除外番号・理由・入力SHA256を成果物へ残す。

## 入力境界

- ペリフェラル初期化の調査では、CubeMXの分割生成を仮定してspi.c/tim.cを検索パスへ指定しない。最初に `rg -n "MX_SPI2_Init|BaudRatePrescaler" robotrace_v2/Core/Src -g "*.c"` のように実在ディレクトリを検索し、結果に出たファイルだけを読む。このプロジェクトのSPI2初期化はmain.cに存在する。

- 過去の解析成果物やテストを読む前に、rg --filesまたはGet-ChildItemの実在名と照合する。系列ごとの成果物名を推測しない。詳細は[推測パスの再発](../../../../doc/失敗事例/2026-08-11-windows-rg-glob-not-expanded.md)。

- CSVは拡張子だけで選ばない。basenameがASCIIの `^[0-9]+$` に一致するものだけを整数化し、数値の範囲・件数・欠落番号を照合する。`imu_temp_*.csv`、boost、bin/part/tmpは別形式。
- 既存の `analysis/script/check_additional_logs_13238_13247.py` の `discover()` を参照する。新しい処理へ流用するときも呼出契約を読む。
- メタデータ・ヘッダ・全データ行の列数を検査する。末尾空セルは仕様として別に数え、欠損列名とは区別する。固定長読込なら物理行末まで読む。派生列も含む実CSVの列数を使う。
- 整数相当メタデータはfloatへ変換後、有限・整数相当・範囲を検証してint化する。`2`/`2.00`は受理、`2.5`/`nan`/`inf`は拒否し、端数を切り捨てない。
- 短い行・非数値・NUL・改行不整合は番号と理由を記録する。全件分類では個別例外で全体を止めずABNORMALへ分ける。NUL除去は読込コピー内に限り、破損フラグを残す。有限値なしでnanmaxや平均を呼ばない。
- CSVイテレータはファイルのwith内で消費する。描画へ渡すCSV数値列は文字列のままにしない。新規標準ライブラリ参照はimport一覧と実行の両方で確認する。

## 時刻・距離・単位

- U16 cntlogの65535→0の既知折返しは、対応形式と連続性を確認して解析側だけ65536 msを加算する。任意の逆行を折返しとして救済しない。時間重みを作る前に正差分を確認する。ユーザー方針により、この対策のためファームの時刻形式は変更しない。
- 距離基準ログに固定の11ms上限や特定速度の3～7mm範囲を流用しない。logDistanceTargetMm、速度、1ms量子化、残余持越し、期待行数、raw左右積算平均の距離差を合わせて欠落を調べる。大きな時刻間隔だけで処理落ちと断定しない。
- load境界でraw積算と補正座標を区別する。DISTANCE/SLIPのencTotalOptimal後退は、マーカー遷移と当該コード・設定の補正上限を照合する。後退を一律拒否も無条件許可もしない。物理進捗・記録間隔の健全性はraw左右平均の差分とlogDistanceTargetMmで確認する。補正座標は正差分だけ抽出しても小さいマーカー補正を含むため、記録間隔の検査へ使わない。新規解析の図生成前に一次・DISTANCEを含む代表ログでload/metricsを実行する。詳細は[補正距離の正差分での再発](../../../../doc/失敗事例/2026-10-04-corrected-log-distance-backsteps.md)。
- XY再計算では計算版を先に確認する。現行版2はraw左右累積値の平均距離差と保存済みimuAngle_Zの両端平均を使い、負差分・半パルスを保持する。encTotalOptimalのマーカー補正を混入させない。旧版1のXYは補正距離から計算された過去値として区別し、新版のXYと同じ意味に読み替えない。疎なgyro再積分は旧形式の近似として明示する。
- mm/msの数値はそのままm/s。encCurrent[pulse/ms] / PULSE_MILLIMETERでm/s、加速度gにはGRAVITY_MPS2を掛ける。速度の既知範囲と距離/時間の独立計算で換算を確認する。

## 完走・比較条件

- 新判定の実走対象・書込境界は、ユーザー指定、実機書込証跡、保存メタデータ、原本ハッシュを別々に保持して照合する。同じ版・閾値・ビルド時刻が旧新対象に共存する場合、記録一致だけで初回新判定・変更後本数を断定しない。2026-10-18の訂正では新二次13505以降、一次13504を横誤検出の陰性対照とし、13500～13503は新評価件数へ含めない。詳細は[対象所属の訂正](../../../../doc/失敗事例/2026-10-18-slip-cohort-metadata-ambiguity.md)。

- XYずれを許容幅に使う比較では、ログ自体の健全性・ユーザー指定基準・PATH経路元の適格性を分ける。一次のclosureValid=0/reason=8を、正常終了した指定XY基準の一律拒否へ流用しない。閉路値/理由を別に残し、PATHの±60mm制限は変更しない。詳細は[比較基準と経路元の混同](../../../../doc/失敗事例/2026-10-18-xy-reference-route-eligibility.md)。

- 連番やemcStop=0だけで完走としない。モード、終了メタデータ、期待行数、経路終端または当時のゴール条件を確認する。右マーカー数はSG加算数ではない。PATH系は経路弧長終端を使い、旧ログへ現在のSG回数を押し付けない。
- autoStartは系列・一次参照・run番号1～5と全走の完走を確認する。1本でも欠落・失敗・未完了ならセット全体を採用比較から除外し、診断用として残す。
- 中断を含む系列の集計前にprimaryLogNumberで所属を作り、観測run・欠落run・停止ログを確認する。一次番号からの5連番で次系列を補わない。正常PRIMARYの単独診断と完了系列の性能比較を分ける。確認例は[中断系列の所属](../../../../doc/失敗事例/2026-10-16-interrupted-series-log-membership.md)。
- 性能の計算前に、方式、要求方式、run番号、一次/SLIP参照、速度表全体、加減速/lead、PID、FF、電圧、校正、スキーマ、ビルドを比較表へ出す。同一gitCommitでもSD設定は違う。終了ヘッダのPIDはchangeGain()による動的切替値の場合がある。
- 通常性能と低電圧ストレス・手持ち/空転を分ける。平均・最小電圧と比較適格理由を出し、過去の電圧しきい値を固定ルールへ戻さない。
- PWM/電圧飽和とlapの相関を因果や改善と呼ばない。速度追従、スリップ、完走、出力余裕を同じ条件内で評価する。

## イベント・推定・集計

- 閾値の疎な残差リプレイ前に全走のTotalMs/ValidMs/IntervalReasonと瞬時Validを検査する。開始42msのみ無効を他走へ流用しない。区間内の有効位置が分からない混合区間は任意配置せず除外し、全有効かつ両端有効な区間だけで近似する。実記録有効時間と近似採用時間を分け、無効境界で継続状態をリセットする。詳細は[途中低速・再充填](../../../../doc/失敗事例/2026-10-18-slip-replay-validity-segments.md)。

- 最新の正解ラベルの決め方は[XY→動画→最終ラベル](../../../../doc/slip-evaluation-policy.md)を参照する。先に基準一次とのXY差を判定し、その後動画を確認する。動画不確定時はXYを正として閾値調整に使い、動画が明確な場合は動画を採用する。基準一次の未特定・欠測を正常ゼロで埋めない。

- 横補正候補版2は候補専用ON 5.0/OFF 4.2m/s²をslipLatCandidateOn_mps2/Off_mps2へ記録する。既存slipLatOn_mps2/Off_mps2は初回SHADOW横4.6/3.8の意味を維持する。版1の過去比較と版2を同じ閾値として混ぜない。正解窓は動画の動きと実画像で確定し、想定周回数で件数を固定しない。詳細は[候補閾値版2](../../../../doc/slip-lateral-candidate.md)。

- 6点校正の初期化を800/1100/1400pxだけで十分と仮定しない。13500～13503では500/650/800/1100/1400/2000pxの開始値を確認し、fit点と実測高さのコストだけで解を選んだ。候補コスト・画素所属・独立留保残差を保存し、同じ別解に収束した場合も品質ゲートを緩めない。

- 動画の床校正では可視点数を明示し、未観測点をfitデータへ補完しない。可視点が少ない場合はfit_pointsで追跡の配列境界も揃える。数値初期値を再探索するときはfit点と実測高さだけのコストで解を選び、候補・採用コストを保存して独立留保点で検証する。留保点・走行ログ・滑りラベルで解を選ばない。

- 動画の床校正は、点数一致・ソルバーsuccessだけで受理しない。機体上の赤系領域を床点と混同していないか実画像で確認し、fit点と未使用の留保点の残差をprepare/track/analyzeの各入口で検査する。品質ゲート超過は追跡前に停止し、修復は実測画像の対応付けだけで行う。13438～13442では10mm以上を停止条件とし、これを物理位置誤差上限や滑り閾値へ読み替えない。詳細は[床点所属の再発](../../../../doc/失敗事例/2026-10-17-video-color-marker-identity.md)。

- 撮影モード/解像度/fps変更時は実ファイルのPTS・寸法と実画像の床点所属を再確認し、旧動画の画素座標をそのまま使わない。追跡開始前に、校正と追跡で同一の復号/スケーリング/HSV/重心/可視条件を使用しているか、同じ静止フレームを両経路へ通して検査する。床点変化量が初期画像でも大きい場合は、品質ゲートを緩めず抽出条件の差を調べる。不可視点を近傍の別マーカーで補わず、可視性が確認できた参照時刻と根拠を保存する。手法修正前の中間物を保全し、方法版・元画像ハッシュ・旧新有効率・独立シーク中心照合を出す。詳細は[復号と床色域の不一致](../../../../doc/失敗事例/2026-10-17-video-color-marker-identity.md)。

- 13500～13503では、全連結成分を抽出した後に中心のROI内外・床点近傍で候補を絞り、色マスク自体の切抜き・床点周囲塗潰しをしない方式を検証した。ROI外の成分は欠測とし、残った断片へ中心を寄せない。事前検算にも本体と同じ候補選別条件を適用する。旧17走の定量不採用は再追跡するまで維持する。

- 全動画の追跡に進む前に、ROI境界に近い走行中の実フレームで全色成分とROI後の面積・中心を照合する。床点凸包は機体マーカー全体を囲むとは限らない。ROIで色成分を切断した重心を真の中心とせず、ROIは候補中心の絞込みに使う。独立中心検算が不合格なら動画の定量採用を止め、ログの健全性とは分けて不採用を記録する。正常なゼロへ置換せず、動画不確定なら指定XY基準へ戻す。詳細は[ROI切断の追記](../../../../doc/失敗事例/2026-10-17-video-color-marker-identity.md)。

- 動画照合では、色・面積・既知の中心間距離だけでマーカー所属を確定しない。校正の留保床点、時間的連続性、外れ値の前後実画像を確認し、ログのgyroに合わせて追跡値を修正しない。補間表示と有効観測を分け、各走・評価窓の被覆率と欠測を保存する。集計前に各走・各窓幅の有効窓件数を確認し、0窓なら品質未達として速度指標は未記録、窓数・被覆率は0で保存し、他走の集計を継続する。0窓のassert停止や品質ゲート緩和、正常ゼロへの置換は行わない。PTSはパケットの提示順・件数を照合する。詳しくは[動画色マーカーの所属](../../../../doc/失敗事例/2026-10-17-video-color-marker-identity.md)。

- 周回照合前にCROSS全件の時刻・保存積算方位を出す。13514の開始4ms/方位約0.05度の追加CROSSのように位相照合できない場合、そのログだけXY未判定として保持し、他ログの数値・ON位置集計は継続する。原本の先頭イベントを0へ置換して検査を通さない。詳細は[先頭CROSS照合](../../../../doc/失敗事例/2026-10-18-initial-cross-lap-validation.md)。

- CROSS存在と姿勢フィット品質は別に検証する。品質不足イベントだけ理由付きで除外し、有効通過数と実際の比較周回数を出す。飛ばしたイベント間を1周と数えない。
- CROSS確定には検出位置と幅確認の遅延がある。IMU位置同定では独立ラインイベント・素子位置・アンカー±20mm感度・積分則感度を確認する。最適値の安定だけで物理レバーアームを採用しない。
- Yaw融合では学習/留保を固定し、ソルバー終了理由・制約到達・数値検算・物理妥当性を分けて出す。gyro地図や設計DXFへの距離を真のYaw精度と呼ばない。平均地図/各一次地図/独立形状で参照依存性を確認し、評価結果で係数を選び直さない。
- 解析ユーティリティは必要キーと前処理を読む。既存Yaw解析の依存順はwindows→attach→observation_masks。
- 直線形状・指令加減速・観測Yawは別ラベル。ぶれの解析で実gyroの小ささを直線選別に使わない。
- 空の方式/区間は集計行を作らず標本数を残す。主表だけでなくログ別・感度表・全図入力も有限値検査し、JSONはallow_nan=Falseで保存する。欠測を0や正常値へ置換しない。
- 曲線は同一系列内のxを昇順・重複なしにしてから結ぶ。数値誤差上限は離散式・保存型から導き、assert失敗に合わせて恣意的に緩めない。全グラフを保存後に確認する。

- 校正prepareを組み立てる前に、新動画の初期像と旧床点探索中心の重なりを確認する。床マーカー据置・同解像度でも画角の据置とは限らない。ずれた旧画素を可視点として扱わず、今回実画像で所属を確認した床点の実測中心を使う。シーク画像生成execがsession_idを返したら、write_stdinで終了コード0・新画像の実在を確認してからview_imageへ進む。詳細は[午前動画での追記](../../../../doc/失敗事例/2026-10-17-video-color-marker-identity.md)。

- 過去文書に凍結スキーマ名が記載されていても現チェックアウトの存在を保証しない。`rg --files robotrace_v2/Core/Inc -g "log*"`で現行のlog_schema.h/logBinary.h/logSource.hを列挙してから読む。V2正式採用後は旧凍結ファイルを解析の前提にしない。
