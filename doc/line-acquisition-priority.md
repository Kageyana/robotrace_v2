# 白線取得を制御計算より優先する修正

13877/13878では、TIM6のIRQ区間最大約502µs・1ms超過0でも、白線更新間隔が最大6ms、鮮度3ms以上が23.94%だった。100ms連続の有効照合が回復条件であり、この間欠欠測は減速を解除できなくする条件になり得る。今回は取得側を修正し、鮮度/停止/回復の閾値は緩めていない。

## 変更内容

- `initSystem()`でタイマー開始前にTIM6優先度を3へ変更する。TIM3=1・ADC DMA=2を先に処理し、LED位相/ADC完了を制御計算中にも進める。CubeMXの初期値0・`.ioc`・生成ピン設定・500µs PWM周期は変更しない。運転時の優先度3はアプリ側の明示設定とする。
- 制御/停止判定/ログが読むraw10個・正規化10個・更新件数を1ms処理の入口から末尾まで固定する。ADCは2サンプル×ON/OFF平均化を継続し、最新の完成値と件数を末尾で一括公開する。途中の電源世代変更は保留値を破棄し、重複ONでは保持する。
- 校正の位置判定も短い割込み禁止区間で10個をコピーする。マーカーの1byte公開値をvolatileとし、既存の判定内1回読取りを維持する。
- 保存列56/154B・62/163Bと既存の単位は維持し、メタデータに`lineAcquisitionPolicyVersion=2`と設定上の`lineControlIrqPriority=3`を追加する。保存テストのShortcut境界3ケースは3603～3618B/4096Bに収まった。
- 120µs安定待ち・50µs走査余裕・鮮度3ms未満・全暗100未満20ms停止・白線信頼度の停止/回復・速度0検出後のPID出力2秒保持を維持する。PID/FF・SDの速度表・補正率は変更していない。
