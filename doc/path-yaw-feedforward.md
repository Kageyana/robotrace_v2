# PATH_CURVEの旋回FF版2（制御版20・実走検証候補）

13894は周回間の相対横変位が約1.4mmへ減った一方、カーブ出口で横偏差が約25mmに達し、機体の一部が板外へ張り出した。有効白線と1ms取得を保った状態での過渡追従偏差であり、白線喪失停止の緩和や位置融合係数の変更では対処しない。

従来のFFは、最近傍から先読み先までの方位差を弦長で割り、目標速度を掛けていた。先読みの全距離ぶん曲率変化を先行させる一方、減速中の実移動速度は目標より高い。13894の5.35秒は目標1.258m/s・車輪速度2.086m/sだった。保存指令とgyroの近似同定は遅延6ms＋時定数5ms、速度の集中時定数は48ms。疎な保存値を用いた診断であり、機体の確定モデルではない。

FF版2はPATH_CURVEだけを次の方法へ変更する。

- UIの先読み距離を曲率平均窓の幅に使い、窓中心を実移動速度×10msだけ先行させる。
- 隣接点の方位差を各区間で±180度に補正し、窓との重なり弧長で平均する。全窓の総旋回が180度を超えても別名へ丸めない。
- 同じ1msの自己位置更新で使用したエンコーダ移動量[mm/ms＝m/s]を0～10m/sへ制限し、曲率に掛ける。実速度0ならFF0とする。非有限移動量の喪失停止と±1800deg/s上限は維持する。

PATH/SHORTCUTは従来のFFを使用する。横/方位FB、速度表、加減速、位置・方位融合版3、白線地図版2、取得版2、各停止条件、2秒の停止出力保持は維持する。SD設定を書き換えず、現在の先読み40＋20v、K lateral10、K heading20、位置係数5/追加方位勾配0を使う。

`routeControllerVersion=20`、`pathYawFeedForwardVersion=2`、`pathYawPreviewTime_ms=10.00`、`pathYawSpeedSource=encoder_1ms`を記録する。通常56列/154B・詳細62列/163Bと診断6列の順序・単位は維持し、`pathYawFF_dps`の算出方法だけがPATH_CURVEで変わる。

## 検証の範囲

実Cを使ったPC専用コピーでは、完全な自己位置/白線観測を仮定し、近似の速度・旋回応答を通して閉ループを比較した。速度の使い方2種×曲率窓6種×応答8種の96ケースと、別一次3本の72ケースを評価した。実測に近い応答条件では、最大横偏差は約25→5mmになった。ただし、これはモデル内の数値であり、新コードでの実走や板内走行の証拠ではない。

旋回の遅延15ms＋時定数15msという遅いストレス条件では、10ms候補の最大偏差/RMSが従来より悪化する。悪化例は除外せず、全結果を`analysis/path_heading_20261029_002102/steering/velocity_curvature`と`cross_geometry`に保持した。候補は観測された応答を基準に選び、実機の応答が大きく変わる条件まで採用済みとはしない。正式採用には独立した実走・変更後10本以上の再現性確認を要する。

実機用Cの曲率関数は、非等間隔・部分重なり・方位折返し・全窓420度・不正入力・端点を独立解析値で7693ケースずつO0/O2/Wall/Wextra/Werror検証した。実型RoutePointと実定数を使用する。正式Cと候補のモデル比較は、x87の拡張評価精度を両側同じfloat保存条件へ揃えて8応答条件の全CSVバイト一致を確認した。ARMの物理応答を再現する証明ではない。

15保存走行のO0/O2計30再生で有限値・0.2mm/0.02deg補正上限・±1800deg/sを確認した。新しい13894の固定入力再生は喪失なし・末尾未照合0ms・最大1217deg/s・TRACKING中の飽和0。観測運動を固定した反実仮想であり、操舵変更後の完走予測には使わない。

通常/詳細ログの実保存・全CRC・PC再変換、FFの実速度/停止/符号/メタデータ、既存のPATH/SLIP/欠測周期、白線融合O0/O2回帰が成功した。現在の13894メタデータ3719Bに対し、新3項目を追加しても4096Bバッファ内に収まる。最初の新形式実ログも別途確認する。

## 実機への反映

書込み/起動の正は`build/path-yaw-ff-validation/validation.json`。書込み前に既存の制御版19とのFlash一致と出力0を再確認する。最初の確認ではST-LinkがTarget no device foundで接続できず、新版の書込み前に停止した。13894のRAMは保全済み。

初回は現在と同じ3.4m/sの設定で、新一次→PATH_CURVEの動画/ログと、電源保持した走行後RAMを確認する。新しいIRQ時間・取得周期・板外張出し・過渡偏差・速度追従を評価し、悪化時はその事実を保持する。モデルだけで増速や本採用へ進まない。
