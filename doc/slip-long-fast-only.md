# 縦スリップのFast単独判定比較

2026-10-14、`codex/slip-detector-v2`。ユーザー指示に従い、SHADOWの縦判定からSlow窓のAND条件だけをON・OFFとも外した。初期閾値・継続時間の評価を混ぜず、両窓条件を外す効果を比較する。

|条件|版2：変更前|版3：変更後|
|---|---|---|
|ON|Fast・Slowの絶対値が両方10 m/s²超を3ms連続|Fastの絶対値10 m/s²超を3ms連続|
|OFF|Fast・Slowの絶対値が両方8 m/s²未満を5ms連続|Fastの絶対値8 m/s²未満を5ms連続|
|メタデータ|`slipDetectorVersion=2`|`slipDetectorVersion=3`, `slipLongPolicy=fast_only`|

閾値と等しい値はON/解除を進めず、8～10 m/s²の範囲では直前の状態を保つ。無効入力時は従来どおり窓・フラグ・継続カウンタを初期化する。

5ms平滑化、10/30ms残差、43サンプルの窓充填、有効性、電流/PWM補助診断、横・旋回・横接線補正候補は維持する。LongSlowをFastの代替閾値や解除条件へ使わず、計算・記録は続ける。列は追加しない。通常72列/183 B、詳細87列/220 B、CRCと旧6形式の識別を維持する。

`slipV2Flags`の縦ビットと`slipV2OnLongMs`の意味は新条件へ変わる。`slipV2PeakLong`は両窓の最大絶対値のままなので、Fast単独のピークとは扱わない。列構成だけで版2/3を識別できないため、比較ではメタデータを確認する。不明なら判定方針を未確定とする。

従来の`slipFlag`・`slipFlagLat`、距離補正、SLIP次走速度計画、共通IMU処理は変更しない。閉路X・減速区間の修正も含めない。版3はSHADOW比較用であり、実走行制御への採用ではない。

## ローカル確認

作業直前の実Cソースを`analysis/slip-long-fast-only/before-slipDetection.c`へ保存し、現行版と同じ1ms入力で比較する。短い空転・制動滑り、持続不整合からの回復、10/8ちょうどの境界、ヒステリシス、通信失敗・再充填、低速・停止・再スタート、区間リセットを検証する。

比較は9083周期。縦フラグが異なる周期は1472、Fast単独でONかつSlowがON未満627周期、SlowがON超でもFast回復でOFF133周期、旧版だけがSlow回復待ちでON415周期だった。これらは合成入力による仕様確認件数で、実機検出率ではない。許可した縦フラグ・縦継続カウンタ・縦ON時間以外の全状態はビット一致した。

実行コマンドは`python analysis/script/validate_slip_long_fast_only.py`。検出器・従来出力・候補横残差の回帰、ログ互換・CSV変換・復旧・不正ログ拒否、DISTANCE/SLIP計画比較、Debug/Release×通常/詳細ビルドがすべて成功した。結果は同フォルダの`build-validation.json`と各ログ。候補追加時の回帰比較では今回意図した縦フラグ・縦ON時間を除外し、専用比較で別途検証する。

静的RAMはDebug 88056 B、Release 87776 Bで変更前と同一。検出器状態1640 B、スタック予約8192 Bを維持し、新規warningなし。検出器のオブジェクトに倍精度ヘルパー依存はない。変更前に保存したCore全ソースのハッシュと照合し、ファームウェア変更は`slipDetection.c/.h`とメタデータ追記の`SDcard.c`だけと確認した。1ms側の更新・ログ保存成功後の区間クリア・メイン側のSD実書込という所有関係を変更せず、共有状態や新しい割り込み処理は追加していない。実機の最大スタック使用量と検出性能は未検証。

## 実機確認

書き込み・実走行・DWT計測は今回行わない。最初のログで版3/fast_only、列数、縦ON時間、有効時間、cntlogを確認し、版2と同方式・同程度の電圧で比較する。縦イベントの位置・符号・短さ、加速/制動/旋回過渡との関係を分け、単なるON率増加を精度改善と呼ばない。最低10本の比較と実機採用判断は別途行う。既存5mm間隔CSVから1ms継続フラグを完全再現したとは扱わない。
