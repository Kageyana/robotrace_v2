# PATH_CURVEの白線未照合中の再加速を保留する版21

版20/FF2の13898は、白線照合を失った初期区間で速度目標が約1.50から2.31m/sへ上がり、終了時は未照合150ms・停止7となった。ユーザーは実際の板外逸脱を確認した。別一次13900の成功10走を保持したうえで、この既知の失敗を改善対象にする。逸脱の瞬間の動画はなく、再加速が直接の物理原因だとは断定していない。

版21はPATH_CURVEで有効な白線照合が不成立の周期に、計画目標を直前の制限済み目標以下へ抑える。明部があるだけでは解除せず、残差超過・地図欠測・鮮度切れ・無効な観測も保留対象になる。計画上の減速は通し、照合復帰後は従来のSD加速度で加速する。CAUTIONの速度上限と100ms回復、喪失停止、全暗部20ms停止は維持する。PATH/SHORTCUTへ追加保留は適用しない。

補正率・停止閾値・曲率FF版2・速度表・SD設定は変更しない。新しい計算は既存の1ms目標更新内の条件分岐とminだけで、割り込み内へ待機・I/O・確保を追加しない。実機の1ms処理時間は新しい像で別途確認する。

メタデータは`routeControllerVersion=21`と`pathUnmatchedAccelHoldVersion=1`。既存56/62列・154/163B、単位、順序、CRC、PC変換は維持する。新メタデータの初回実ログ確認は書込み後の走行で行う。

検証入口は`validation/path_unmatched_speed/run.py`。実センサー判定と実追従器を通して、有効照合、暗部、残差超過、地図欠測、古い取得、無効校正、複数群、予定減速、100ms回復、方式分離、喪失停止をO0/O2で検査する。13898/13899と13901～13910の12走×O0/O2を、先に凍結したPC案へ全トレース比較する。固定した保存運動の再生であり、板外防止や実タイムの予測ではない。正常ログにも速度目標の低下があるため、走行時間への影響を実機で確認する。

全4ビルド・両保存形式・PC変換の証跡は`build/path-unmatched-speed-validation/validation.json`。版20の全14原本・10走の完走確認・9動画・失敗13898は`analysis/path_yaw_ff_20261029_repeat9`に保全する。新しい方針の実機採用は、書込み照合、停止起動、最初のログと物理挙動を確認して判断する。
