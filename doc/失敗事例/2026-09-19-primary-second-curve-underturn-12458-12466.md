# 一次走行の二つ目のカーブで旋回目標・実旋回が不足する

## 要約

12458～12466の9本はすべて約1.4～1.5mで終了し、ユーザーが完走ログと指定した12368の約4.7mに達していない。偽ゴールの5本も経路元として拒否された。初回解析では12439・12441・12444を完走基準と誤認し、最初の左マーカーが約180mm早いと報告したが、12368を基準にすると成立しない。以下は訂正後の分析。

## 発生した状況

- タスク: 36Bログ、ADC位相対策、時間計測、偽ゴールの事後拒否を導入した後の走行確認。
- 比較対象: ユーザーが完走ログと指定した12368。旧ファームウェア・異なる設定とバッテリー電圧であり、制御条件は同一ではない。
- 12458は旧ビルド、12459～12466は時間診断を備えた同一の新ビルド。

## 何を試したか

1. `analysis/script/analyze_primary_runs_12458_12466.py`で累積エンコーダ距離に整列して比較した。
2. 走行時間、マーカー、割り込み、ADC、カルマン、ログ欠落診断を照合した。
3. `cf86014..1e72269`と未コミット差分のうち、一次走行のセンサー・目標角速度・距離・IMU周期処理を追跡した。
4. `analysis/script/scan_primary_build_history_12368_12466.py`で途中の一次走行ログ60本のビルド、終了距離、最初の左マーカー記録位置を調べた。

## 結果・エラー

- 12368の最初の左マーカー記録は461mm、失敗9本は462～472mm。初期カーブの位置ずれは認められない。
- 500mmでの角速度目標は12368で641deg/s、失敗9本278～531deg/s。最初のカーブから目標・ジャイロとも小さい。700～1000mmでは保存XYのY差が約15～20mmだが、旧新でXY積分方法とジャイロログ値の意味が異なるため、全差分を実際の横ずれと同一視しない。
- 1300mmでの角速度目標は12368で約870deg/s、失敗9本の中央値約450deg/s。1400mmでは12368が約880deg/s、失敗9本の中央値0deg/s。12368の曲率半径は1400mmで約76mm、失敗走行では直線相当の値まで増え、外側へ膨らむ。
- 新形式8本の1ms割り込み最大223～224µs・超過0、IMU読出し最大47µs・エラー0。ライン更新最大2ms、位相不一致0の走行が7本ある。12459だけ更新最大3ms・古い観測1回・位相不一致1回。
- 新形式8本で距離カルマンのinnovation reject、ログオーバーフロー、スタート検出から原点リセットまでの時間・パルス差はいずれも0。36Bで左右エンコーダ列は残り、レコード数はヘッダと一致。
- 12458・12459・12460・12462・12465は`closureReason=4`で偽ゴール無効。残り4本は`emcStop=5`でライン喪失、`closureReason=2`。
- `cf86014..1e72269`ではラインセンサー処理、マーカー処理、モーター出力コードに変更がない。一次走行の角速度目標`(senR-senL)*encCurrentN >> 9`も同じ。PIDcontrol.cのコミット差分は速度PIDの入力整理だけで、旧側もスリップ距離補正が無効で生エンコーダを使用していた。
- コミット間で距離積算は生エンコーダからIMU/エンコーダ融合へ、IMU校正は1ms×1000回から20ms×100回へ、1ms処理はエンコーダ距離更新をIMU読出し後へ変更した。`PULSE_MILLIMETER`は誤った54.324から53.424へ修正された。
- 400～1400mmの保存サンプルで、失敗ログの`encCurrentCorr_p - encCurrentN`は最大絶対値1パルス/1ms、平均-0.04～+0.01パルス/1ms。融合後距離の大きな連続偏りは観測されない。ただし保存サンプルは全1msを網羅しない。
- 12458は22:22ビルド、12459～12466は23:13ビルドで、同じ`gitCommit=1e72269`でも未コミット内容は異なる。ADC位相ラッチ・鮮度ガード等は後者の作業ツリー差分だが、失敗は前者でも発生している。コミットIDだけでは実行バイナリを一意に特定できない。
- 同じ短いコースとみられる記録は、12368の後、12448まで見つからない。途中の一次走行は左マーカー約645mm・全長約37mの別条件が多い。したがってログだけで中間コミットへの回帰時点は特定できない。
- 12448～12453の最初の`1e72269`ビルド（18:48）ですでに1.1～1.4mで失敗している。12452の終了ヘッダ角速度FB`kp=5`でも約1.39mで終了した。ただし旧ログには走行開始時ゲインがないため、`kp=5`は終了時の値に限る。

## 原因

未確定。今回測定した割り込み時間超過・継続的ADC位相不一致・リセット遅延は共通原因を支持しない。一次走行の目標角速度はライン左右合成値と生エンコーダ速度から作られ、角速度FBの`kp`と曲率FF（BOOST_DISTANCE専用）とは別である。最初のカーブから不足する目標値により二つ目のカーブのライン観測が変わった可能性はあるが、現行36Bログには個別10センサー値がないため断定できない。旧新のXY積分方法も異なる。距離融合の保存サンプル差は小さく、大きな距離ずれの根拠はない。旧新でIMU校正・周期順序とPID設定が違う。低速走行では電圧差の優先度を下げるが、正規化ラインセンサー値は速度に関係なく目標角速度へ直接入るため校正同等性は未確認のまま残る。23:13の計測追加と`kp=13`への変更は、18:48時点ですでに失敗していたことから単独原因ではない。

## 解決・回避策

未解決。高速走行・経路生成へ進めず、まず12368相当と現行の実行バイナリ・設定の差を固定して比較する。低速で450～600mmと1050～1400mmの短い範囲に限り、個別10ラインセンサー値とマーカー生値を採取し、二つ目のカーブで目標が低下する前に何が変わるか調べる。通常の36B走行ログには恒久的な重い診断列を追加しない。

## 今後の予防策

一次走行の設定変更後は、同一コースの確認済み完走ログ番号とビルド時の未コミット差分を先に確認する。今回は12368の最初の左マーカー461mm、1300mmの旋回目標約870deg/s、1400mmの目標約880deg/sを比較起点とする。ただしビルドと設定が違うため閾値として固定せず、個別センサー値と実際の軌跡で検証する。修正後は同条件で物理的ゴール通過を10走以上確認する。
