# SLIP解析で画面が Analyzing のまま進まなかった

## 要約

オートスタートの `12717.csv`（一次）と `12718.csv`（DISTANCE）が保存された後、3走目の画面が `Analyzing / SLIP 12718` で30秒以上変わらなかった。

## 確認できた事実

- `12717.csv` は `closureValid=1`、`distanceScaleVerified=1`、`emcStop=0`、585行。
- `12718.csv` は `optimalTrace=2`、`emcStop=0`、575行。最終 `optimalIndex=115`。
- ローカルのCSVは読み取り可能で、行数とヘッダに明らかな欠落はなかった。
- `readLogDistanceSlip()` は一次ログを読む `readLogDistance()` と前走ログ読込の両方で、通常時にもSDを再マウントしていた。再マウントはカード初期化と空き容量走査を伴う。
- 実機の停止箇所は未計測であり、再マウントが直接原因かどうかは未確定。
- 追加の `12732`～`12735` でも、一次走行とDISTANCE走行のログは正常終了・保存されたが、3走目の解析画面で再発した。各CSVの列数と必須値に欠落はなく、2走目の最大 `optimalIndex` は489と491で、一次距離から推定する約502区間内だった。
- 通常時の再マウントを省いても再発したため、再マウントだけを主因とする推定は支持されない。`sd_spi.c` の単一バイトSPI転送には `HAL_MAX_DELAY` が使われ、解析全体にも時間切れ判定がない。SD読込待ちが停止箇所という見方は仮説であり、実機の段階計測が必要。
- `12739`～`12742` は4走目のDISTANCEログまで保存されたが、5走目の画面が `Analyzing / SLIP 12742` のまま停止した。3走目固有の問題ではない。
- 修正版でも `Analyzing / SLIP 12746` で再発した。前回のSDエラー経路の修正だけでは解決していない。
- `12750` の後は `Analyzing / SLIP 12750 / Base read 512` から進まず、5走目のモーター動作もない。SLIP専用ログ読込より前の、一次ログの再読込中に停止している。
- ログは `F:` に無かったが、`C:\Users\ucawa\Dropbox\Document\robotrace\Log\v2` に `12747`～`12750` があった。`12747.csv` は585データ行で、1行は最大152文字。513行目以降にも明らかな欠落や長すぎる行はない。
- 4走目のDISTANCE走行は同じ一次ログの距離計画を正常に生成し、`PPAD[]` を用いて走行済み。5走目SLIPで同じ一次ログを再読込する必要はない。
- 解析中に `f_error()` が立っても、SLIPログの読込ループは診断をSDカードへ書いてから読み続ける実装だった。この分岐を実機で通過したかは未確認。
- ST-Linkプローブは認識されたが、SWDでSTM32ターゲットに接続できず、停止時の実行位置は取得できなかった。

## 対処

- 同期・クローズ済みログの通常解析では再マウントを省き、オープンまたは読込のI/Oエラー後の再試行時だけ再マウントするよう変更した。
- Debugビルドは成功した。実機での3走目移行は未確認。
- SD読込エラー時の診断はITM出力に変え、同じSDへの書込を除去した。SLIP読込中の `f_error()` は即座に `-5` として終了し、既存の1回だけの再試行に進むよう変更した。
- SPI単一バイト転送の `HAL_MAX_DELAY` を20 msの有限待機へ変更し、転送失敗をSD読込・書込エラーとして上位へ返すよう変更した。
- 解析時のI/Oエラー再試行で使う再マウントは、空き容量の全走査と自動フォーマットを実行しない形に変更した。
- 修正後のDebugビルドは成功した。実機のSLIP解析完了は未確認。
- `endLog()` が同期とクローズを終えた後の解析開始で行っていた `sd_flush_log()` 呼出しを除去した。追加同期が停止箇所だったかは未確定。
- 解析画面に `Base read`、`Base plan`、`Slip open`、`Slip read`、`Slip plan` の段階と読込行数を表示するよう変更した。
- SLIP開始時に、直前DISTANCEで生成した一次ログの距離計画が有効なら `PPAD[]` を再利用するよう変更した。条件が合わない場合は従来どおり一次ログを読む。
- 計画再利用の変更後、Debugビルドは成功した。実機でのSLIP走行開始は未確認。

## 再発防止策と確認方法

- 解析開始後にSDを再マウントする変更では、カード初期化・空き容量走査の回数と、連続2ログ解析の所要時間を確認する。
- 実機で1走目DISTANCE解析と3走目SLIP解析の両方が完了し、3走目カウントダウンへ進むことを確認する。
- 再発する場合は `readLogDistance()` 完了、スリップログのオープン、読込終了の各位置に時間計測を追加して停止箇所を特定する。
- 上記の再発を確認した。次回は解析の段階表示またはシリアル時刻記録で停止箇所を確定し、SPI転送の無期限待機を含めて対処する。
- 実機で確認できた場合だけ `resolved` に変更する。
- 新しいファームを書き込み、再現条件でSLIP解析からカウントダウンに進むか確認する。SD障害があれば `Failed / Error -5` 等として停止し、`Analyzing` のまま残らないことを確認する。
- I/O障害時の再マウントでSD内ファイルが消去されないことを確認する。
- 次回再発時は画面最下段の段階と行数を記録し、その段階に絞って原因を調べる。
- `Base cached` が表示され、次に `Slip read`、カウントダウンへ進むことを確認する。次回 `Base read` が出た場合はキャッシュ条件のどれが不一致か調べる。
