# 分割コミット準備で保存ソースの収録範囲を共通と仮定した

## 同作業のGit内容照合とUTF-8 BOM

prepare.pyのutf-8-sig復号がHEAD・保存コピー・作業ファイルのBOMを除去し、BOM以外が一致しているstage1のlog_schema.hをindex照合で拒否した。実indexは元のEF BB BFを保持していた。コミット作成前に停止し、開始時indexが空だったことと対象7パスを照合して、自分が追加したステージだけを解除した。作業ファイルとHEADは保持した。

予防はGitペイロードの復号をutf-8とし、BOMを内容として保持すること。CSV読込のutf-8-sig規約をGitオブジェクトのバイト比較へ流用しない。修正prepare.pyで全入力存在・段階別BOM保全・全隣接空白を検査し、適用後はindex実バイトをペイロードと全件照合してからコミットする。旧検証ペイロードと新ペイロードは先頭BOMを除く全内容の一致を確認し、中間ビルドの証跡を保全する。status: resolved（BOM保全の生成と照合手順）。

- 対象: 2026-11-01の未コミット変更を6段階へ分ける作業。
- 事実: クロス直線化前のコピーにはCore全体がある一方、丸め前速度計画の比較用コピーは対象モジュールだけだった。準備器が両方にSDcard.cもあると仮定し、後者の読込でFileNotFoundErrorとなった。index更新・コミット・作業ファイルの変更は行われていない。
- 原因: 比較用コピーの親Coreの実在だけで、各段階に必要な全ファイルの存在確認を代用した。過去の部分コピーを完全なソースコピーとして扱った。
- 対処: 両コピーの実在一覧を取得し、1段階目は4ファイル、2段階目はpathFollower.c/hだけを参照するよう準備器を修正。他のファイルは前段階から保持する。全必要入力のis_file検査を段階生成の前へ追加した。
- 再発防止: build/commit-staging-20261101/prepare.pyは最初に段階別の入力一覧を確定して全件を検査し、開始HEAD・作業ファイルSHA・各段階のペイロードとパッチSHAを保存する。全隣接段階の空白検査が完了するまでindexを変更しない。
- 確認方法: 修正prepare.pyが終了0、全6段階のペイロード・パッチ生成と全隣接空白検査に成功。隔離ソースで中間コード5段階のビルドを確認してから、index対象と内容を各段階で照合してコミットする。
- status: resolved（収録範囲の確認と生成手順）。各コミット結果とビルド結果はbuild/commit-staging-20261101/へ別途保存する。
