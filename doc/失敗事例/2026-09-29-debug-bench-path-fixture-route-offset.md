# PATHベンチの再生XYが経路元から外れて自己位置ロスト

## 要約

12420.csvの記録XYを12418.csv由来の経路へそのまま設定すると、経路との位置差がロスト閾値を超えた。

## 発生した状況

- タスク: PATH REPLAY/SHORTCUTの空転負荷測定
- 実行環境: STM32F446、Debugベンチ
- 前提条件: 12420.csvは経路元12418.csvと同じ座標系だが、実走行軌跡には経路追従誤差がある。

## 何を試したか

1. 再生ログのXY、方位、進捗をそのままPATH自己位置へ設定した。
2. 次に方位だけを設定し、位置を実エンコーダ積分へ任せた。

## 結果・エラー

```
再生XYと経路元の最近傍点との差は8250 ms時点で約80.7 mmとなり、PATH REPLAYは8345 msで自己位置ロストした。
方位だけを設定した方式も実エンコーダ速度との差により2074 msでロストした。
```

## 原因

記録軌跡と経路元経路は同一座標列ではない。生XYを使うと実走行時の追従誤差が自己位置ロスト判定へ入り、方位だけを使うと空転速度による進捗が再生時系列と一致しない。

## 解決・回避策

12420.csvの時刻・軌跡から算出した距離進捗を、現在のdriveRoute上の位置へ写像し、12420.csvの方位変化を設定する方式へ変更した。実IMU・エンコーダ取得とログ記録は継続する。通常・詳細のPATH REPLAYとSHORTCUT全ケースで36.734秒完走し、経路ロスト0を確認した。

## 今後の予防策

- PATHベンチ fixture は経路元と再生ログを別々に検証し、同一XYとして扱わない。
- 再生距離を経路進捗へ写像するときは、通常経路と短縮経路それぞれの総弧長へ正規化する。
- 実機測定では自己位置ロスト数と停止理由をGDB結果へ含める。
