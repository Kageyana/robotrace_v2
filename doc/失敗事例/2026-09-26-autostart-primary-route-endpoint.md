# ゴール位置が一次ログ終端より先になりオートスタートが停止した

## 要約

PATH系統合後、一次走行のログは保存されたが経路検証の `closureReason=5` で2走目へ進まず、画面は `Written` のままだった。

## 発生した状況

- `main` の `9b727c2` でオートスタートを実行した。
- `12714.csv` と `12715.csv` は `autoStart=1`、`closureReason=5`、`emcStop=0`。手動の `12716.csv` も同じ理由で経路無効だった。
- `12714.csv` の `goalMarkerOnset_p=1457629` は最終行の `encTotalOptimal=1457391` を238パルス超えていた。
- 修正後の `12729.csv` と `12730.csv` では `sgMarkerAtLogEnd=2` なのに `goalMarkerOnsetValid=0`、`closureReason=2` となった。
- 2026-09-27の `12751.csv` では `goalMarkerX_mm=24.48` により `closureReason=8` となった。距離換算検証と正常終了は通っていた。

## 原因

- `main` は幅確認後のゴール判定位置を `goalMarkerOnset_p` に記録した。比較元の `codex/imu-distance-kalman` は、幅確認済みマーカーの検出開始位置を保持していた。
- ログは距離間隔で記録されるため、ゴール判定直後に停止すると、その判定位置が最終行より先になる場合がある。
- 距離換算検証では1ms当たりの `encCurrentCorr_p` をログ間隔分に積算しておらず、終点判定を直すだけでは次の検証で失敗する状態だった。
- 自動走行中の経路検証失敗時に表示を書き換えず、`Written` が残った。
- 追加の不具合として、右マーカーを確認してからゴール判定まで約50mm待つ間に、次のマーカー検出開始処理が確認済みフラグを消していた。`SGmarker` は2へ進んでも開始位置だけが無効になった。

## 対処

- 右マーカーの検出開始位置を保持し、マーカー幅を確認した場合だけゴール位置として採用した。
- 補正パルスをログ行間の経過msで積算するよう修正した。
- 自動走行の停止時に保存失敗または経路検証理由を表示するよう修正した。
- 確認済み右マーカーの位置をゴール判定まで保持し、100mmを超えて未使用の候補だけ破棄するよう修正した。
- Debug ビルドは成功。実機のオートスタート再走は未確認。
- ユーザー指定により、ゴールマーカーX座標の閉路判定上限を±20 mmから±60 mmに変更した。`closureReason=8` は超過または非有限値に引き続き使用する。

## 再発防止策と確認方法

- マーカー位置の取得時点を変える際は、検出開始位置と判定成立位置を区別する。
- 新しい一次ログで `goalMarkerOnset_p` がログの距離範囲内に入り、`closureReason=0`、`distanceScaleVerified=1`、`logExpectedRows` が実行数と一致することを確認する。
- 特に `sgMarkerAtLogEnd=2` と `goalMarkerOnsetValid=1` が同時に成立することを、複数の完走ログで確認する。
- 2走目へ自動移行することを実機で確認できたら、この記録を `resolved` に更新する。
- 閾値変更後は新しい一次ログの `goalMarkerX_mm` と `closureReason` を確認し、±60 mmを超える経路は引き続き拒否されることを確認する。
