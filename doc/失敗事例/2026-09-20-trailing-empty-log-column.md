# CSV末尾の空列を必須列欠損と誤判定した

## 要約

簡易解析で各行の全辞書値が非空か調べたところ、正常な12493～12497の全行を不正と誤判定した。

## 発生した状況

- タスク: 新スキーマログの行欠損、区間、融合XYを確認する。
- 実行環境: Python `csv.DictReader`による読み取り。
- 前提条件: ファームウェアのCSV列名行とデータ行は末尾にカンマを含む。

## 何を試したか

1. 最初は`row.values()`全体に空文字があるか検査し、全行を欠損扱いした。
2. `fieldnames`と実データ行を確認し、末尾の列名と値がともに空文字であると特定した。
3. 空の列名だけを欠損検査から除いて再集計した。

## 結果・エラー

修正後、12493～12497の必須列欠損は各0行。期待行数とも一致した。ログファイルの破損ではない。

## 原因

末尾カンマを`DictReader`が空文字名の列として表現する仕様を、簡易欠損検査で考慮していなかった。

## 解決・回避策

`fields = [name for name in reader.fieldnames if name]`で実際の列名を抽出し、`row[name]`だけを検査する。

## 今後の予防策

- 新スキーマログの行品質検査では最初に列名の末尾と先頭行のキーを確認する。
- 末尾の空列のみ無視し、名前のある必須列の欠損・余剰値、期待行数を個別に検査する。
