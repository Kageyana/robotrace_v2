# オブジェクトの再配置情報の差を生成命令の変更と誤判定した

## 確認した結果

調整用マクロ70個を7モジュールのヘッダへ移動した。Debug/Releaseのビルドは成功したが、追加の比較スクリプトで実行セクションと`.rel.text.*`の生バイトをまとめて照合し、`machine code changed`で停止した。

差分を分けると、DebugのcourseAnalysis/logSource/pathFollowerの`.rel.text.*`だけに差があった。両構成の各40個のCore/Srcオブジェクトで、SHF_EXECINSTRの付いた全実行セクションは変更前後で一致した。Releaseは取得した再配置セクションも一致した。

## 原因と未確定事項

再配置セクションは命令そのものではなく、シンボル表の番号などを含む。生バイトの不一致だけを機械語の変更とする検証条件が過剰だった。今回の再配置差の各シンボルへの正規化比較は行っておらず、差の内訳までは確定していない。

## 対処と再発防止

- 命令の同一性検証はELFのSHF_EXECINSTRで対象セクションを選び、再配置情報とは別に比較する。
- マクロ移動は元の`.c`/`.h`を保存し、名前と定義式の全件一致、移動対象を除いた実装・宣言トークンの一致も確認する。
- 再配置先まで比較する場合は、変更前のオブジェクト自体を保存し、シンボル番号を名前・所属セクションへ解決したうえで再配置種別・位置・加数を照合する。生バイト比較だけで動作変更と結論しない。
- flash-debugのビルド検証前参照へ上記の判定条件を追加する。

## 確認方法とステータス

修正後の`build/verify_tuning_parameters.py verify`が成功し、両構成各40個の実行セクションの一致、全定義式と実装・宣言トークンの一致を`build/tuning-parameters-20261025/verification.json`へ記録した。検証条件の誤判定を修正・確認できたためresolved。実機書き込み・走行確認は行っていない。
