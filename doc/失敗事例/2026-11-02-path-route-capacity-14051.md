# 一次14051のPATH解析が経路容量不足で-7になる

- 対象タスク: 機体UIで一次14051をPATH用に解析した際のError -7調査と修正。
- ステータス: open（ビルド確認済み。機体への書込みと実UI再解析は未確認）。
- 事実: PCに保存された14051.csvは期待7208行と実7208行が一致し、全行の列数が一定で全数値が有限。XY折線長は36,028.9166mm、encTotalOptimalからの距離は36,028.9216mm、マーカー新規イベントは86件。原本SHA256は`14896d073a0ea8377cc5f92d0a31fa05c6558178f3245c5d770285868d563e33`。
- 原因: `pathAppendRouteSample()`は20mm間隔で点を追加し、`PATH_ROUTE_MAX_POINTS - PATH_GOAL_RESERVED_POINTS`到達で失敗する。従来1800点・予約13点では基準経路の終点まで約35,720mm。14051は始点・末尾点・予約を含め1816点相当を必要とするため容量不足。マーカー86件は上限192件以内。
- 対処: 初めに1850点で両構成を確認後、ユーザー指定の最終設定である`PATH_ROUTE_MAX_POINTS=2000`・`RUN_MEMORY_MAX_BYTES=60KiB`へ変更。既存の36m容量static assertのメッセージも36mへ統一し、AGENTS.mdを更新。2000点では約39.7mの一次と終端延長を保持できる。20mm間隔、配列構造、1ms割込み、停止条件は変更しない。
- メモリ確認: 最終Debug/ReleaseのmapでRunMemoryは`0xcad0`=51,920 Bで60KiB以内。1850点の中間ビルドでは`0xbc2c`=48,172 Bだった。PathMarkerAnchorは10 Bであり、経路配列25 B/点とマーカー192件を含むサイズを4 B境界へ切り上げる。1900点では49,420 Bで旧48KiB制限を268 B超過し、旧上限内の最大は1889点（49,148 B）。初回説明ではマーカーを12 Bと誤算したが、リンクmapで訂正した。
- 再発防止: 点数変更前に、一次の全XY長・20mm間隔・予約13点・始終点から必要点数を計算する。`sizeof(RunMemory)`のstatic assertとDebug/Releaseのリンクmapで共有RAMの現行上限・全体128KiB・予約スタック8KiBを確認する。点数だけ増やして共有RAM上限を超えない。RAMの計算は構造体サイズを推測せず、実際のmapと照合する。
- 検証: CMake Debug/Releaseのconfigure/build成功、最終2000点で両構成を再ビルドし終了0。最終リンク表示RAMはDebug 89,256 B、Release 89,328 Bで128KiB以内。両mapの予約スタックは`0x2000`=8KiB。変更したヘッダに起因するwarningなし。既存ソースにはADC/DMA・SD書込みのポインタ型、表示関数の宣言・const、LED初期化に関するwarningが残る。差分は点数・容量説明と記録文書に限定し、割込み関数の変更なし。
- 未確認: 原本binがPC保存先にないため全CRCと機体が読んだbinの同一性は未確認。PCでの実C再生試験は実行承認が拒否され未実行。書込み後、静止状態のUIで14051をPATH解析し、正の解析結果・保持点数・正常な開始準備を確認する。実走行と最大スタック使用量は別途確認する。
