# 補正ログ追加時の検索ガードとパッチ入力

- status: resolved（検索とパッチ手順）。実機ログ検証は対象外。
- 対象タスク: PATH/SHORTCUT/PATH_CURVEの白線・マーカー補正ログ分離。
- 事実: Test-Pathでrobotrace_v2/testsがFalseと表示された後も、同じ呼出しのrgへそのパスを渡しos error 2となった。後続コマンドは実行された。加えて、単一apply_patch内に同じpathFollower.cのUpdate Fileを2回置き、multiple operations targetとして拒否された。
- 原因: 存在確認を表示だけで済ませ、nativeコマンドの入口ガードへしていなかった。パッチもファイル単位で統合していなかった。製品差分を再確認し、拒否されたパッチの部分適用がないことを確認した。
- 対処: 実在するvalidationのみで一覧取得し、検索終了コードを個別に確認した。パッチは同じファイルの変更を1つのUpdate Fileへまとめ、再適用成功と差分を確認した。
- 再発防止: 必須検索先が存在しなければthrowで停止し、任意の検索先は存在するパスだけを配列へ集めてrgへ渡す。Test-Pathの結果表示後に固定リストを使い直さない。rg終了コード2以上で停止する。パッチ作成時は操作対象パスの重複を除き、同じファイルのhunkを1操作へまとめる。共通事前確認とビルドSkillの実行前参照へ反映する。
- 確認方法: validationを起点としたrg終了0、拒否直後のgit diffに製品差分なし、統合したパッチの適用成功と4製品ファイルの差分を確認。record-failures Skillは公開一覧・個人Skill・プラグイン配下検索に存在しなかったため、このリポジトリ規定の保存先へ手動記録した。

## ホストCRC試験のポインター型

- 事実: 実logBinaryCrcUpdateの引数はconst uint8_t *だが、合成schema/metadataのconst char *をそのまま渡し、ホスト検証がWpointer-sign（Werror）で停止した。変更前ホストのコンパイル・制御トレースは完了済みだった。製品のビルド不良ではない。
- 対処: 合成バイト列をconst uint8_t *へ明示変換した。警告条件は維持し、実Cの補正/保存試験と通常・詳細×O0/O2の全4組で成功。全ヘッダ・データ・スキーマ・メタデータCRCと独立復号を確認した。
- 再発防止: CRCフィクスチャ作成前に実APIのポインター型と符号を照合し、テキスト表現とバイト列への変換を呼出し側で明示する。ビルドSkillの実行前参照へ反映する。
- status: resolved（合成試験の型と検証）。実機保存・PC変換器での確認は別途。
