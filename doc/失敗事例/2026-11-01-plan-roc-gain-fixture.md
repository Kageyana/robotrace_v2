# 計画ROCの進入・復帰条件は同時成立する

- 対象: 計画ROCだけによるゲイン切替の実C境界検証。
- 確認した結果: 初回ホスト検証で、4点先=500 mm・2点先=3000 mmのカーブ進入理由を6と期待したassertが失敗した。
- 原因: 進入と復帰で先読み位置が違うため両条件が同時に成立する。既存のreason bit3は「保持中かつ復帰ROC条件成立」なので進入直後にも立ち、正しい値は14（bit1/2/3）となる。制御の不具合ではなくfixtureの期待値の誤り。
- 対処: 実装の理由ビット生成を確認し、同時成立を明示した期待値へ修正した。製品の閾値・保持処理・理由生成は変更しない。
- 再発防止: 別の先読み位置を参照する進入・復帰を排他的と仮定しない。両方成立・片方成立・両方不成立の真理値を、理由ビットと保持距離の境界試験へ含める。
- 確認方法: `validation/plan_roc_gain/run.py`をO0/O2で実行し、4万判定の旧方式（実測十分大）との一致を照合する。
- 検証結果: O0/O2で境界・終端・リセット・モード分離・4万判定の実測独立性が成功。旧14034の実測単独進入31件を固定入力で照合し、新版では直線となることを確認。通常/詳細の保存・全CRC・型付き読込3用途も成功。Debug/Releaseは既存6 warning・新規0 warning、RAM増加なし。
- 証跡: `build/plan-roc-gain-20261101/validation.json`。実機閉ループの改善は未確認。
- ステータス: resolved（fixture前提を修正、実機の切替挙動は別途確認）。
