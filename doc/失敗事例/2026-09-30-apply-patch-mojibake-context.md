# 文字化けコメントを含むCコードで差分適用の文脈が一致しなかった

## 要約

既存コメントが文字化けしたCソースで、コメントを含む行を差分の照合対象にすると複数回パッチ適用に失敗した。失敗したパッチは適用されず、後続の広範囲置換で別関数に入った行変更はビルド警告で検出して戻した。

## 発生した状況

- タスク: ログ取得距離を10 mmから5 mmへ変更
- 実行環境: Windows、PowerShell、Codex `apply_patch`
- 前提条件: `courseAnalysis.c` の既存コメントに文字化けがあった

## 何を試したか

1. 周辺コメントを含む複数行の差分を適用した。
2. 表示上のコメント文字列を文脈に含めて再試行した。
3. ASCIIのコード行だけを照合する差分と、対象行を特定するUTF-8保持の行編集へ切り替えた。
4. トークンだけで行置換した際、別関数の同名行まで変更したため、対象関数の範囲へ修正を限定した。

## 結果・エラー

```
apply_patch verification failed: Failed to find expected lines
```

## 原因

失敗は差分適用時の文脈照合で起きた。`courseAnalysis.c` のコメントはソース上でも文字化けしており、表示されたコメントを期待文字列として再利用しても一致しなかった。トークンだけの置換では、同じ識別子を持つ別関数へ範囲が広がることも確認した。

## 解決・回避策

ASCIIコード行を基準に差分を小さく分割し、コメント行を照合文脈から外した。複数行を置換する必要がある箇所は、UTF-8と改行を保つ行単位編集を使った。別関数へ入った行変更を元に戻し、Debugビルドで警告が出ないことを確認した。

## 今後の予防策

- Cソースの差分は、文字化けコメントを文脈アンカーにせず、識別子や制御文などASCIIのコード行を使う。
- 適用失敗後はコメントを含む大きなパッチを繰り返さず、対象範囲を縮めてから再適用する。
- 行単位スクリプトでは関数または行範囲を先に限定し、変更後に `git diff` で同名行への漏れを確認する。
- コメント自体を修正する場合は、周辺のコードから意味を確認して日本語UTF-8で書き直す。
