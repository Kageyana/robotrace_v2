# 白線照合を失った初期区間でもPATH_CURVEが再加速する

- status: open
- 対象: 周回ずれとコースアウト防止、制御版20/FF2、一次13897・走行13898。
- 確認結果: ユーザーは逸脱・板外へのはみ出しを確認し、場所を「長い直線のカーブを曲がって次のカーブを曲がろうとしたとき」と説明した。動画なし。8.085秒で自己位置喪失停止7、未照合150ms、終了信頼度0。未照合初期7.937～7.996秒の実保存速度目標は約1.50→2.31m/sへ増えた。
- コード上の条件: 有効照合がなくてもCAUTION閾値へ届く前は計画目標へ加速できる。単一の明部があることは地図との有効照合を意味しない。30mmの照合残差上限や全暗部20ms停止を緩めて対処しない。
- 原因/未確定: 端点保持白線・区間平均運動・鮮度正常を仮定した凍結再生でも未照合末尾149msが再現した。保存実入力の全1ms履歴はなく、差を1ms追加して合わせていない。照合幾何と運動で説明できる可能性があるが、物理原因や対処の因果は確定していない。後の13900～13910のADC正常RAMを13898へ転用しない。
- 対処: PC専用Cコピーで有効照合なしの周期は目標の増加を保留し、予定減速は許す案を12走へ比較した。失敗区間の再生目標最大2.34→1.50m/s、全12走で未照合中の正加速なし、有限値と固定運動での推定/照合列同一を確認。正常ログにも0.56～1.08m/sの目標低下があり、実タイムと板内走行の効果は未検証。現時点ではPC案で、実機版20は未変更。
- 再発防止: 新しい速度方針は、失敗13898と同一次の正常13899、別一次の成功13901～13910を含め、未照合の初回周期・継続・回復、計画減速、PATH/SHORTCUT分離、緊急停止を実Cで検証する。全4ビルド・両ログ形式・新規メタデータ・1ms経路の責務を確認してから書込む。成功10本の収集を満たしたことと、既知の物理失敗を解決したことを分ける。
- 確認方法: analysis/path_yaw_ff_20261029_repeat9/validation.json、failure_13898.json、unmatched_acceleration/validation.json。全14原本CRC/CSV/56列、24凍結再生、PC12比較をSHAとともに保存した。実機対処後の初回ログと物理確認が得られるまでopenとする。
