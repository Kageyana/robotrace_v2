# PATH REPLAYがヘアピン出口の近接経路点へ飛んで逆旋回した

## 要約

PATH REPLAYが小R左旋回へ進入する直前に、ヘアピン出口側の経路点を最近傍点として選択した。経路indexと方位目標が不連続に飛び、左旋回指令から右旋回上限へ反転して3走連続で`STOP_LOCALIZATION`となった。

## 発生した状況

- 対象一次走行: 12289、12291、12293
- 対象PATH REPLAY: 12290、12292、12294
- ファームウェア: `gitCommit=e56359a`、`branch=main`、`routeControllerVersion=2`
- PATH REPLAYはすべて`shortcutLevel=0`、`emcStop=7`
- バッテリー開始電圧: 7.61 V、8.18 V、8.15 V

## 何を確認したか

1. 一次走行のXY点列を40 mm間隔で再標本化し、経路方位を再計算した。
2. PATH REPLAYの`optimalIndex`、`linePointX_mm/Y_mm`、方位偏差、目標角速度、実ジャイロを時系列で確認した。
3. 経路indexの不連続ジャンプと旋回指令反転の時刻を3走で比較した。

## 結果・エラー

```text
12290: index 320 -> 335、対応点間22.2 mm、方位偏差 -9.61 -> +114.91 deg、目標角速度 -258 -> +1800 deg/s
12292: index 320 -> 336、対応点間23.4 mm、方位偏差 -9.01 -> +119.86 deg、目標角速度 -232 -> +1800 deg/s
12294: index 320 -> 336、対応点間22.5 mm、方位偏差 -8.35 -> +122.66 deg、目標角速度 -220 -> +1800 deg/s
```

正しい一次経路はindex 320付近から左ヘアピンへ入り、経路方位が約+1.5 degから負方向へ連続変化する。出口側index 335～336は入口から実空間で約20 mmしか離れていないが、経路に沿った距離では600 mm以上先で、方位は約+96 deg異なる。

## 原因

`pathFollowerUpdateTarget5ms()`の最近傍探索が、現在indexの4点後方から24点前方までをユークリッド距離だけで比較している。候補点の経路方位差や、5 msで物理的に進める経路距離を評価していないため、近接するヘアピン出口側を選択した。

indexジャンプ後は先読み方位偏差が約+120 degとなり、目標角速度が右旋回上限の+1800 deg/sへ飽和した。したがってモーター出力の左右反転ではなく、経路対応点の誤選択が逆旋回の直接原因である。

## 解決・回避策

経路制御バージョン3として、実際の`driveRoute`から累積弧長を計算し、対応点候補を補正後エンコーダ累積進行距離の120 mm先まで、かつ推定機体方位との差60 deg以内に制限した。候補がない場合はindexを保持してロスト回数を加算し、100 ms継続した場合だけ既存のフォールバックまたは`STOP_LOCALIZATION`へ移る。

履歴ログ12290、12292、12294では、問題のジャンプが15、16、16点であることを解析スクリプトが検出した。コード実装とビルド確認後も、実機12本の採用基準を満たすまでは本記録を`open`のまま維持する。

## 今後の予防策

- PATH系ログで`optimalIndex`が1サンプル間に5点以上進んだ場合を自動警告する。
- 小R、ヘアピン、交差、並走区間では、空間距離が近く経路距離が離れた点対を経路生成時に検出する。
- 修正後は同じヘアピンで、index連続性、目標角速度符号、方位偏差、`pathState`を確認し、3系列計12本で再現性を評価する。
- Level 1ショートカット検証はLevel 0 PATH REPLAYの3系列計12本完走後に行う。
