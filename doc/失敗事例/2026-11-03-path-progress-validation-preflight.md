# 白線進捗補正の検証入口と比較条件

- 対象：制御版30のマーカーなし自己位置補正。status: resolved（検証入口と比較契約）、open（実走改善と実機処理時間）。ファーム・原ログの破損は確認していない。
- 事実1：マップファイルの読取でPowerShell Select-Stringへ`\_`を渡し、.NET正規表現の未定義エスケープで停止した。その呼出しでソースは変更していない。後続ではrgの実在ファイル検索へ切り替え、`_`をそのまま指定して状態800Bを確認した。
- 事実2：初回の固定入力再生で、新補正OFFの代わりにlineAlpha=0を設定し、既存白線EKFも同時に無効化した。結果を新補正単独の効果比較へ使っていない。製品Cの新補正呼出しだけを薄いテストラッパーでON/OFFするよう修正し、EKFと実ログ15速度項目を両側で維持した。14084は修正後のOFFでも実停止7を再現しないため、改善効果を証明したとは報告しない。
- 事実3：ヘッダ容量試験の実関数抽出が`void`だけに限定され、実在する`static void setLogHeaderStrFPrecision`を抽出できず、コンパイル前に停止した。static修飾を含む定義パターンへ修正して再開した。既に完了した制御試験やビルドの結果を上書きして失敗扱いにしていない。
- 事実4：最終のARMスタック計測を-Wextra/-Werrorで実行すると、uint16_t同士の減算がintへ昇格するため、`high - low > 1U`で符号比較警告となった。ホストZigの同一警告指定と通常ファームの-Wallでは検出されなかった。差分が非負である二分探索の不変条件を維持し、比較前のuint32_t変換で修正した。警告抑止は追加していない。
- 再発防止：比較前に各ON/OFF側で変える変数・呼出しを列挙し、既存EKF・速度設定・入力・鮮度仮定を固定する。記録済みoptimalIndexを正解として与えず、実最近傍選択を動かす。関数抽出では実シグネチャを先に読み、static修飾とプロトタイプ除外を含め、全必要関数を抽出できてから最初のコンパイルを開始する。PowerShellの検索パターンでは英数字・アンダースコアを不要にエスケープしない。
- 手順反映：robotrace-tuning Skillの実行前手順へ、新補正だけを切り替える比較契約・実停止未再現の留保・実関数抽出の事前検査を追加する。
- 追加手順：ホストの厳密警告検査だけで完了にせず、新モジュールをARM GCCでも-Wall/-Wextra/-Werrorで直接コンパイルする。最終入口のスタック計測で両最適化構成を同条件で検査し、ソース変更後はそのソースを使う検証を更新する。
