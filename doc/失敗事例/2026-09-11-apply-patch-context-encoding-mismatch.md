# 文字化けコメントを含む広いパッチの文脈不一致

## 要約

既存Cファイルの文字化けコメントを広いパッチ文脈へ含めたところ、`apply_patch`が対象行を一致できず2回適用に失敗した。コードは変更されず、短いコード行だけを文脈にした分割パッチで作業を継続できた。

## 発生した状況

- タスク: ログスキーマと解析元記録の追加。
- 実行環境: Windows PowerShell、UTF-8/既存文字化けコメントを含むCソース。
- 前提条件: `courseAnalysis.c`へ複数の関数とグローバル変数を追加する必要があった。

## 何を試したか

1. 既存コメントを含む複数行コンテキストでパッチを適用した。
2. 実ファイルの行を確認し、コメントの文字列が表示結果と一致しないことを確認した。
3. コメントをパッチ文脈から外し、安定したコード行だけに分割した。

## 結果・エラー

```text
apply_patch verification failed: Failed to find expected lines
```

## 原因

確認できた事実は、パッチの期待文字列に含めた文字化けコメントが実ファイルのバイト列と一致しなかったことである。コメントの文字コード変換そのものが起きたかは未確認である。

## 解決・回避策

コメントを含まない短いコード行をアンカーにしてパッチを分割した。既存コメントの修正は今回のログ変更とは別の範囲として行わなかった。

## 今後の予防策

- 文字化けコメントを含む既存Cソースへパッチを当てるときは、コメントを期待文脈に含めない。
- パッチ前に対象行を行番号付きで確認し、グローバル変数・関数宣言など安定したコード行をアンカーにする。
- パッチ失敗後は`git diff`で部分適用の有無を確認してから再試行する。
