# フォント配列と記述子で同じ挿入目印が重複していた

## 確認した結果と原因

71ファイルのコメント見出しを追加する初回スクリプトで、`ssd1306_fonts.c`の`#ifdef SSD1306_INCLUDE_FONT_7x10`が2箇所あり、一意性検査が停止した。フォント配列と記述子の両方が同じ条件で囲まれていた。既に62ファイルを更新しており、編集箇所ごとの検査だけでは一括処理の途中停止を防げなかった。Cコード自体の変更はなかった。

## 対処と再発防止

挿入位置を条件行と`static const uint16_t Font7x10 [] = {`の組へ限定した。作業開始時の保存コピーを基準に全71ファイルの編集案をメモリ上へ生成し、全件の目印の一意性、コメントを除いた論理行の一致、マクロ継続行、USER CODE境界の一致を検査した後にだけファイルへ書き込む方式へ変更した。途中まで更新されたファイルも、同じ開始時コピーから再生成した。

共通事前確認へ「一括編集では全件の編集案を検査してから書く」を追記する。単一の条件行や汎用的なコメントが一意とは仮定せず、対象の宣言まで含めて位置を特定する。未知の一致数は編集前に停止し、対象の取り違えを置換件数の緩和で回避しない。

## 確認方法とステータス

修正後の`build/unify_core_sections.py`が全71件の事前検査を通過し、各ファイルへ両見出しを追加した。`build/core-sections-20261025/verification.json`に全件のコードとUSER CODE境界の一致を保存した。差分の空白検査も成功した。一括編集の挿入位置と書込順序の修正は検証済みのためresolvedとする。
