# ログ番号抽出の正規表現が対象ファイルを欠落させた

## 要約
11273〜11371のログを列挙する際、正規表現の代替パターンを誤って `11273〜11279` と `11300〜11371` に限定し、11280〜11299を一時的に欠落扱いにした。

## 発生した状況
- タスク: 11273〜11371のログ比較。
- 実行環境: Windows PowerShell、`F:\Dropbox\Document\robotrace\Log\v2`。
- 誤った抽出条件: `1127[3-9]` と `113[0-6][0-9]` の組み合わせ。

## 何を試したか
1. 正規表現で対象ログを列挙した。
2. 取得結果を見て、11280〜11299が存在しないと一時判断した。
3. 数値範囲をPowerShellで比較し直し、99本すべて存在することを確認した。

## 結果・エラー

```text
初回列挙: 11273〜11279、11300〜11371
再確認後: 11273〜11371の99本
```

## 原因
`1127[3-9]` は11273〜11279だけに一致し、11280〜11299には一致しない。正規表現の見た目から連続範囲全体を表していると誤認した。

## 解決・回避策
ログ番号を文字列パターンではなく、ファイル名を数値化して下限・上限で比較した。解析スクリプトは指定範囲を数値で走査し、欠落ファイルを明示する方式にした。

## 今後の予防策
- 対象範囲の期待本数と実ファイル本数を必ず比較する。
- 欠落番号を `range(start, end + 1)` で算出して表示する。
- 正規表現で列挙した場合も、最終的に最小番号、最大番号、件数、欠落番号を検証する。
