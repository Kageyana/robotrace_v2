# Windowsのパス区切りでソース照合対象が空になった

- 対象: ショートカット初回ログ14045～14047の解析とコミット前のソース一致確認。
- 事実: validation.jsonのsource_sha256のキーはWindowsの区切りを含んでいたが、照合側がforward slashの文字列prefixで絞り込んでいた。対象0件でallが成立し、ソース一致確認を行わず成功扱いした。コミット前の出力で対象が空であることを確認した。生成器自体のO0/O2検証・全経路一致・実走ログ解析結果は保全した。
- 原因: マニフェストのパス表記と絞込み条件を照合せず、空の検証集合を拒否していなかった。
- 対処: analysis/script/analyze_shortcut_14045_14047.pyのprepareをPath.partsによる階層判定へ変更し、対象がC/Hの2件であることを先に検査する。コミット前の検証にも同じ規則を適用した。
- 再発防止: パス由来の検証対象は文字列表記に依存せず階層で判定する。ハッシュの全件一致を調べる前に期待対象数・対象名を検証し、0件を成功にしない。ログ解析Skillの実行前手順へ追加する。
- 確認: forward/backslashの両表記を階層で受入れ、無関係パスを除外する境界を確認。実マニフェストからCore/Src/pathFollower.cとCore/Inc/pathFollower.hの2件を抽出し、現在ファイルのSHA256一致を確認した。修正版prepareで3ログの入力検証とソース2件の照合が成功。
- ステータス: resolved（照合入口）。この修正で製品コード・設定・経路生成処理は変更していない。
