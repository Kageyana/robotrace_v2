# Shortcut画面を無変更時も消去・再描画した

## 確認できた結果

ユーザー動画PXL_20261025_072623505.mp4（3.3006秒）の抽出フレームで、No.8 Shortcutのヘッダが表示されたまま本文の文字が部分的に消える状態を確認した。動画原本は変更せず、抽出画像はbuild/shortcut-ui-flicker-20261025/contact.pngへ保存した。

追加したsetup_shortcut_paramは全呼出しで本文を消去し、数値・項目名・単位・操作案内を書き直していた。ssd1306の連続DMAはSSD1306_Bufferを直接参照し、コールバックから各ページを再送する。このため消去から再描画完了までの中間バッファも転送し得る。またsetup末尾は連続DMA稼働中にも同期UpdateScreenを呼んでいた。修正前の実setup.cを保存した再発テストで、無変更時の繰返し消去とDMA中の同期転送を両方検出した。

## 原因・前回検証の不足

前回のUIホスト検証はキー入力、表示文字列・幅、数値範囲、SD保存を確認したが、描画の回数と非同期転送の状態を模擬していなかった。表示更新を同期的な完了処理として扱い、消去途中のバッファが転送される条件を見落とした。動画だけから他の物理的要因を否定したとは扱わない。

## 対処・再発防止

- 入場・項目変更時にだけ本文を消去・描画し、値変更時は数値行を21文字幅の空白埋めで上書きする。無変更時は描画バッファを触らない。
- setupの同期転送は連続DMA停止中だけ行う。走行制御・SD設定形式・表示ドライバの転送実装は変更しない。
- UI変更前に実ssd1306のバッファ所有者、DMAの開始・停止・コールバック、同期転送の呼出元を確認する。モックでは無変更1000周期の再描画ゼロ、値変更時に本文全消去なし、ページ再入場の再描画、No.0～8のDMA稼働中同期転送ゼロと停止中の転送を検証する。
- 書込み・デバッグSkillのホストUI検証前へ同じ確認条件を追加する。
