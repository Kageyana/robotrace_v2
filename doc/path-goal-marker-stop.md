# ゴールマーカー確認後の通常ライン追従停止（制御版26）

13989～13991・13993はユーザーがコース完走を確認したが、ゴール後の経路延長中に白線未照合150msで自己位置喪失停止になった。ユーザー指定により、PATH / SHORTCUT / PATH_CURVEも他方式と同じゴールマーカー判定で通常停止へ移る。

## 変更

- control.cのcase12は全方式で`SGmarker >= COUNT_GOAL`（現行2回）を確認し、goalTimeを記録してenc1・停止保持状態を初期化し、patternTrace=101へ移る。延長経路の終端到達は正常終了条件に使わない。
- case101の既存処理を使う。ゴール確認後50mm未満はtgtParam.stop、50mm以降は速度目標0。TIM6はpatternTrace>100で通常ラインPIDと平均速度PIDを更新し、経路追従・自己位置更新・白線照合監視の走行処理を実行しない。
- 平均エンコーダ速度0の初回検出後、速度目標0のPID出力を2秒保持する。保持中は操舵0。完了後にcase102で出力0とし、既存のログ確定・自動次走判定へ進む。
- ゴール前の完全逸脱停止・自己位置喪失停止・緊急停止優先は維持する。既にemcStopが発生していれば通常完走へ置換しない。
- 原点方向の経路延長は先読み用として残す。周期未確定時の延長白線地図そのものを生成する変更ではない。ゴールマーカー未確認時に未照合が続けば引き続き緊急停止する。
- 経路制御版を26へ更新する。ログ列・単位・SD形式・マーカーの幅確認や距離による計数条件は変更しない。

## 確認

`validation/goal_marker_stop/run.py`で実case12/101、停止保持関数、TIM6の制御分岐・緊急停止判定を抽出して、変更前後×O0/O2・Wall/Wextra/Werrorで検証した。各実行40条件のモード・SG回数・経路終端フラグ比較と、全5方式のPID切替、50mm境界、2秒境界、tick周回、保持中のPID出力変更、ゴール同時の緊急停止優先、ゴール前の停止5/7を確認した。timer.c全バイト、case102以降の保存・緊急停止処理、停止保持関数は作業前と一致する。

`validation/goal_marker_stop/build.py`で変更前の全体ビルドと変更後のDebug / Releaseを確認し、新規warningなし。既存warningは改行を正規化した種類数で各5件。結果と実ELFは`build/goal-marker-stop-20261101/`へ保存した。Debugのビルド後に警告比較のCR差だけで集計が停止したが、実ELFと原ログを保全し、集計のみ再開して成功した。

## 実機確認

未書込み・実走未確認。初回実ログでrouteControllerVersion=26、ゴール規定回数、emcStop=0、ゴール付近での記録終了を確認する。ログ記録は既存のpatternTrace=11～99範囲なので、ゴール後の全制動履歴は走行CSVに残らない。実機ではゴール確認後のライン追従、50mm区間後の制動距離・停止位置、2秒の保持を確認する。変更前の4走を新仕様の実機成功本数へ加算しない。
