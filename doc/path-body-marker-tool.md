# 前後色点による方位計測器の準備

周回ずれを機体の横位置と方位へ分けるため、`analysis/script/measure_body_marker_heading.py`を用意した。取付方法は[次回撮影の手順](path-independent-heading-measurement.md)。今回は実機/ファームウェア/SD設定を変更していない。

元解像度1920×1080の画像と今回の床校正を使い、赤/黄の全色成分を測ってから機体ROI内の中心を選ぶ。確認済みの静止前後点、面積、同じ取付平面、同一撮影条件と床安定化を必須とし、複数候補/欠測/画像端/間隔不足/面積比異常/HSV感度過大を棄却する。角度をgyro、移動方向、輪郭角で補完しない。

90条件の既知角合成画像を確認し、最大差は0.733degだった。欠測等10条件では角度null、同高点の投影36条件、元画像の成分をROIで切らないことを確認した。これは合成検証で、実機の精度保証ではない。13922の元解像度5通過にも未確認の前後点を当てはめず、実方位は採用していない。

前後点の世界高さが違うと見かけのYawが変わる。今回のカメラモデル・3位置/3方位では、高さ差±1mmで最大1.221deg、±5mmで最大6.087degになった。同じ上面へ付けても走行中のピッチ/ロールの影響が残る。HSV/1px感度を動的誤差の信頼区間と呼ばず、必要精度に対して十分か実動画で確認する。

静止参照テンプレートは`analysis/body_marker_heading_preflight/reference_template.json`。未確認フラグは全てfalseで、座標/面積は未入力。新しい撮影の静止画像を確認してから設定する。合成例の座標、旧128mm間隔、以前の校正や画像位置を流用しない。

入口は`measure_body_marker_heading.py`の`--image`、`--calibration`、`--camera-index`、`--reference`、`--roi`、`--output`。現在のCLI検証は未確認参照で不採用・角度nullになることを確認済み。新しい動画が届いたら、原本SHA・初期床点・前後色点・撮影高さ/解像度・静止ばらつき・ぼけを確認してから走行区間へ使う。まず1本で識別性を確認し、同版の追加9走/10走を一律には要求しない。

画像確認と詳細は[準備検証の報告](../analysis/body_marker_heading_preflight/report.md)、全件結果は同`validation.json`と`readiness_validation.json`。失敗した合成定義と数値検査の経緯は[失敗記録](失敗事例/2026-10-30-marker-synthetic-projection-contract.md)へ保存した。目標のずれ解消は未達で、新しい実測が必要。
