# 丸め前の経路座標による速度計画（制御版25）

13980の最初の長い直線では、速度目標が約4.0→2.8m/sへ低下した。一次13977の経路を20mm間隔・整数mmへ変換した際の小さな段差が、速度計画で約R802mmの曲率として扱われていた。制御版25は、20mm間隔に再標本化した時点の小数座標から曲率半径を求める。接線方位も速度計算時は0.01度へ量子化せず、半径を最後にmm単位へ保存する。距離窓・速度設定・加減速の式は変えない。

## 実装

- `runMemory.path.drive`を停止中の生成時だけ`sourceXY`として共有し、丸め前のXYを一時保持する。半径確定後は従来どおり整数の実走行経路へ切り替える。
- `RoutePoint`の末尾2byteを、基準経路`line`では`sourceRadius_mm`、実走行経路`drive`では`speed_cms`として使う。`RoutePoint`は8byte、共有RAMは46920byteのまま。
- 周回共通地図では、従来と同じ弧長位相・周期・閉じずれ分配を小数座標にも適用してから半径を求める。追従用の整数地図、接線方位、白線地図の生成は維持する。
- 半径はキャッシュに保持し、速度設定を変えたときは毎回その速度表で計画を作る。半径の生成失敗・共有RAMの切替では有効性を落とす。
- SHORTCUTで形状を変更した点と前後2点、およびゴール延長の接続・延長部分では、変更後の整数形状から従来どおり曲率を再計算する。クロス前後100mmの直線化を優先する。
- 1msの自己位置更新・追従計算、FF、白線補正、退避・回復・停止条件には処理を追加しない。ログ列・SD形式は維持し、`routeControllerVersion=25`で識別する。

## 検証

`validation/path_unrounded_speed/run.py`は変更前コピーと現行の実Cを同じO0/O2・`-Wall -Wextra -Werror`で比較する。斜め直線12方向、R100/200/500/1000/1600mmのCW/CCWと平行移動、端点、非有限入力、周期地図、キャッシュ、短縮区間、共有RAMサイズ、既存の白線・FF・未照合・回復・停止試験を含む。`validation/path_cross_straight/run.py`でも既存のクロス直線化を確認する。

一次13977のCSV XYを型付き入力のモックへ渡した旧新生成では、1721点の整数XY・方位・フラグ・形状CRCが一致。問題の直線（点300～345）の計画速度最低値は2.8→4.0m/s、点326の丸め前半径は8199mmとなった。計画の最大加速度は19.9928m/s²、最大減速度は8.0994m/s²で、設定20/8.1m/s²以内だった。

この試験はCSV由来のfloat32入力による実生成器の比較で、原binの全CRC読込や13980の実閉ループ再走行ではない。ログ非記録のsearch=1、stop=1、shortCut=2、pathReplay=3は試験の仮定で、過去の実SD値の確定とは扱わない。今回のPATH_CURVE中間直線の比較はpathReplay/shortCutに依存しない。

小半径（新半径300mm以下・クロスを除外）の453点では最低速度0.8m/sを維持したが、旧計画に対して最大0.2m/sの増速がある。全体でも最大+1.6/-0.2m/sの変更がある。直線の谷の解消だけで実機の追従・制動・ラップ改善を保証しない。

Debug/Release×通常/詳細ログの全4構成でビルドし、ELF実RAM配置・共有領域と1ms関数サイズ・既存警告との差分を`validation/path_unrounded_speed/finalize.py`で確認する。証跡は`build/path-unrounded-speed-20261101/host-validation.json`と`build-validation.json`。ソース・ELF・元CSVのSHA256を保持する。

## 実機で残る確認

今回の作業では書き込み・実走行を行わない。初回ログで制御版25と設定値を照合し、問題の直線で不要な減速がないこと、急カーブ手前の制動、速度追従、ライン保持、緊急停止の動作を確認する。その後、同条件10本で完走と再現性を確認する。実IRQ最大時間・スタック最大使用量も未計測。
