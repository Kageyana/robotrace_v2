# 四輪スキッドステアのオドメトリ診断

現行機は左右各2輪、左右各1モーター・1エンコーダの構成として扱う。左右エンコーダは車輪の回転を測り、機体中心の横方向速度は直接測らない。旋回中の横滑りをタイヤの向きから一定倍率で補正しない。

解析器: `analysis/script/analyze_skid_odometry.py`。入力ログは読み取り専用で、走行ファームウェア、ログスキーマ、SD設定を変更しない。

## 1. 動力走行による距離換算の確認

室内の直線約1 mを動力走行で3回以上測り、各回の実移動距離と左右エンコーダ値をCSVへ記録する。`powered`は実際に動力走行した場合だけ`1`にする。現在の共通換算値は58,019 pulse/mで、距離校正を変更する前にこの値の妥当性を判定する。

### 現行画面で測る場合

1. ST-Linkなどの配線を外し、室内の十分な直線路で機体を停止させる。車体の同じ基準点を床に記し、実測距離もこの点の移動で測る。
2. 設定画面の`No.4`（`SENSORS`）で`Motor`を選ぶ。画面の左`enc`と右`enc`をそれぞれ開始値として控える。この値は起動後の累積距離表示[mm]であり、毎回ゼロには戻らない。
3. `Duty`と進行方向を確認してから中央ボタンで動力走行を開始し、約1 mで再度中央ボタンを押して停止する。完全に静止した後の左右`enc`表示と、車体基準点の実移動距離[mm]を控える。画面のモータテストは目標距離で自動停止しないため、操作できる位置で行う。
4. 同じ条件で3回以上繰り返す。各回の開始・終了値、またはそれらの差を入力する。表示は1 mm単位で丸められるため、判定では表示差に最大±1 mmの不確かさを加える。床の距離測定も1%判定に十分な精度で行う。

```csv
run_id,actual_mm,left_start_mm,left_end_mm,right_start_mm,right_end_mm,powered
1,1000,20,1020,17,1017,1
2,1000,1020,2020,1017,2017,1
3,1000,2020,3020,2017,3017,1
```

上記は**入力形式の例**であり、実測結果ではない。実測した開始・終了表示の差は、`analysis/skid_odometry/powered_1m.csv`の`left_delta_mm,right_delta_mm`に記録した。

エンコーダ生パルスを別手段で取得した場合は、代わりに次の形式を使う。二つの形式を同じCSV内で混在させない。

```csv
run_id,actual_mm,left_p,right_p,powered
1,1000,58019,58019,1
2,1000,58019,58019,1
3,1000,58019,58019,1
```

```powershell
python analysis/script/analyze_skid_odometry.py distance analysis/skid_odometry/powered_1m.csv --nominal-ppm 58019 --output analysis/skid_odometry/powered_1m_result.json
```

3回以上の全試行で**左右平均の前進距離**の誤差が各±1%以内なら`distance_scale_verified=true`になる。左右個別の誤差は別の`side_scale_verified`で判定する。どちらも表示値を使う場合は丸め誤差の上限を加える。ファームウェアの前進距離は左右平均を使うため、経路用の距離換算ゲートには前者を適用する。

2026-09-21に動力走行の複数回平均として左58,092・右57,945 pulse/mが提供された。左右平均は58,018.5 pulse/mで、整数に丸めた現行の58,019 pulse/mと一致する。続いてDuty 100の個別5走について、実距離と開始・終了時の左右画面表示差[mm]を取得した。

| 走行 | 実距離[mm] | 左表示差[mm] | 右表示差[mm] | 左右平均誤差 | 丸め込みの前進誤差上限 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 998 | 1002 | 1000 | +0.301% | 0.401% |
| 2 | 1002 | 1010 | 1005 | +0.549% | 0.649% |
| 3 | 1003 | 1005 | 996 | -0.249% | 0.349% |
| 4 | 998 | 1001 | 989 | -0.301% | 0.401% |
| 5 | 1011 | 1011 | 1002 | -0.445% | 0.544% |

5走すべてで前進距離の保守的な誤差上限が1%未満となり、共通距離換算58,019 pulse/mを検証済みとした。4走目の右個別表示は実距離との差が9 mmで、表示丸めを加えると上限1.002%になるため、左右個別校正は未検証のままとする。既存の`encCurrentN=(left+right)/2`は1 msごとに0.5パルスを切り捨てる可能性があったため、端数を次周期へ持ち越すよう修正した。これにより累積の前進距離と左右総パルスの平均の差は最大0.5パルスとなる。`PRIMARY_DISTANCE_SCALE_VERIFIED`は1へ更新したが、一次経路の採用には別途IMU校正、正常ログ、ゴール閉合が必要。

Debug/Releaseビルドと正転・逆転のホスト試験を通し、Release ELFをSWDで書き込んだ。書き込み後の一次走行7本については第4節で比較する。10本の計画には未達だが、現時点の採否は取得済み7本で判断する。

## 2. 旋回時の診断

スキーマ9以降の正常な一次走行ログでは、左右の区間パルスと同区間平均ジャイロ角速度から有効トレッドを計算する。速度帯、旋回半径帯、CW/CCW別に中央値と10〜90パーセンタイルを出す。

```powershell
python analysis/script/analyze_skid_odometry.py turn F:\Dropbox\Document\robotrace\Log\v2\12554.csv F:\Dropbox\Document\robotrace\Log\v2\12555.csv --output analysis/skid_odometry/turn_diagnostics.json
```

左右別の提供値を診断として適用する場合は、`--left-ppm 58092 --right-ppm 57945`を付ける。出力には`explicit provisional side scale`と記録され、走行ログ内の校正が有効になったことは意味しない。

左右個別のpulse/mは、ログ上で校正が有効かつ共通換算との差が各2%以内の場合だけ使う。有効トレッドはタイヤ中心間距離とは別の走行条件依存の診断値であり、一次経路の方位積分を左右車輪差へ切り替えない。

保存済みの`12554`〜`12559`では、たとえば1〜2 m/s・半径200 mm未満のCW旋回が約119 mm、同条件のCCW旋回が約114 mmの中央値だった。6本とも`closureValid=0`で、取得時点では距離換算の動力検証も未完了だったため、これは校正値の採用根拠ではない。詳細は`turn_12554_12559.json`に保存した。

同じ6本へ左右別の提供値を適用すると、同条件の各走中央値はCW 118.31〜119.58 mm、CCW 114.27〜114.67 mmだった。共通換算との差はCWで約-0.2〜-0.4 mm、CCWで約+0.4 mmと小さく、左右旋回差は残る。結果は`turn_12554_12559_side_58092_57945.json`に保存した。接地・横滑りの診断値として扱い、経路方位に使わない。

## 3. 横滑りのオフライン候補

横加速度列がある正常な一次走行ログを使用する。機体右を正、CWを正とし、`横加速度 − ヨー角速度×前進速度`を横速度変化の候補とする。直線区間の加速度中央値でバイアスを引き、有限の時定数と速度上限でドリフトを抑える。`x/y`はジャイロを使った中点方位で積分する。

現行スキーマ10の軽量ログに横加速度列はない。新規取得では`ROBOTRACE_LOG_SCHEMA_PROFILE_LIGHT=0`の詳細ログを別ビルドで使用し、121バイト記録によるログ容量・処理時間・オーバーフローを先に確認する。詳細ログでも約10 ms間隔の瞬時値であり、1 ms入力を復元したものではない。

```powershell
python analysis/script/analyze_skid_odometry.py lateral F:\Dropbox\Document\robotrace\Log\v2\12439.csv
```

候補の有効性を判定する際は、上方撮影などで得た独立の軌跡を、同じスタート原点・座標軸・`cntlog`時刻でCSV化して指定する。

```csv
cntlog,x_mm,y_mm
0,0,0
10,0,10
20,1,20
```

```powershell
python analysis/script/analyze_skid_odometry.py lateral F:\Dropbox\Document\robotrace\Log\v2\12439.csv --reference analysis/skid_odometry/12439_camera.csv
```

外部軌跡はログ全区間を覆い、時間同期と座標変換を事前に確認する。出力JSONの`reference_validated=false`なら、軌跡差だけで改善を判定しない。スキーマ6の加速度列は約10 msごとの**瞬時値**であり、実機1 ms入力の区間平均でも厳密な再生でもない。横速度の減衰時定数0.15 sと上限0.5 m/sは比較候補で、採用済みの物理パラメータではない。`12439`、`12441`、`12444`の候補結果は外部基準がなく未検証。

## 4. 書き込み後の一次走行ログ

新ファームウェアの一次走行`12560`〜`12566`を、直前の同モード`12554`〜`12559`と比較した。両群とも`encoderPulsePerMeter=58019`、ライン校正ハッシュ、主要PID・速度設定、36バイトログ形式は同じ。新群の開始電圧7.72〜7.85 Vは旧群7.70〜7.82 Vと一部重なる。新群は7本で、当初計画の10本には達していないが、ユーザーの指定に従ってここまでのログで採否を判断する。

新7本はいずれも`emcStop=0`、保存行数一致、`cntlog`最大間隔12 ms、IMU校正有効、マーカー7個、`gyroSampleFault=0`、`encoderIntervalFault=0`、ログ溢れ0、距離KF棄却・フォールバック・不正更新0、ISR超過0で、XYに非有限値や大きなジャンプはない。左右平均の累積差が旧群119.2〜120.5 mmから新群0.64〜0.88 mmへ縮んだことは端数繰り越し修正と整合する。一方、ゴールXは新群で-44.35〜-79.87 mm（中央値-58.46 mm）、旧群で-44.36〜-59.55 mm（中央値-52.45 mm）。全走が許容±20 mmを超え、`closureValid=0`のまま経路は生成されていない。旧`12559`の-58.04 mmと新`12560`の-58.46 mmはほぼ同じで、後続の変動を端数修正だけへ帰す根拠はない。旧ログを左右生パルス平均で再積分してもゴールXの変化は最大約1 mmだった。

左右別換算での1〜2 m/s・半径200 mm未満の有効トレッド中央値は、新7本でCW 118.29〜119.46 mm、CCW 114.82〜115.16 mm。左右差は残る。`headingCalibration.enabled=0`で、SD上の左右校正値は旧55,036/55,196 pulse/mだが、現行の経路XYはジャイロ方位を用いるため、この設定値は今回のゴールXへ直接適用されていない。閉合の原因は外部軌跡とIMU方位の独立比較が必要。

**現時点の判断:** 共通距離換算58,019 pulse/mと0.5パルス端数の繰り越し修正は維持する。7本すべてでログ健全性と距離積算の改善が確認できた。ゴールX閉合は一度も成立していないため、閾値を緩めず、これらのログをPATH REPLAYやショートカット経路の元として採用しない。横滑り係数や左右有効トレッドを経路方位へ適用する根拠もない。

## 実機へ移す条件

独立した軌跡基準で基準積分より位置誤差p95と終端誤差が繰り返し改善し、別の走行ログでも再現する場合だけ、オンライン推定器を検討する。ライン観測が有効な区間を補正点とし、Level 1直線回廊内のライン位置・方位補正禁止を維持する。制御へ反映した後は同じ走行モード、近い電圧条件で最低10本を取り、完走率、合法余裕、横・方位誤差、ラインフォールバック、対応点ジャンプ、1 ms割り込み時間を比較する。

回廊内の横位置を外部観測できず誤差が支配的な場合、床面光学フローなど独立した横速度観測を検討する。追加ハードの位置・軸・計測範囲は機体・回路資料と実機で検証する。
