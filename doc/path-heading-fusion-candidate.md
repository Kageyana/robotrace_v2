# 白線による方位即時更新の候補

13881は白線取得が毎1msでも、同一床位置5通過の外形重心Yが+16.57mm変位し、一部が板外へ出た。現在の再生自己位置は約+1.9mmしか変位せず、同じ場所の白線照合残差は約9→26mm、位置補正は0.2mm/1msへ達している。現行の4状態共分散は方位を含むが、白線更新のgain[2]を0として、位置とgyro biasへ補正を割り当てていた。

PC専用コピーで方位即時更新ON/OFF×bias推定ON/OFF×位置係数1/5/10を5走へ適用し、全60ケースを検証した。現在と同じSD値alpha=5・追加方位勾配0で、位置＋方位＋bias候補の13881の周回変位差RMSEは12.31→3.21mm、推定変位は+15.75mm。過去13848/13849は2.19→1.31／1.24→1.02mm、低速13878は3.93→4.76mmへ悪化した。5走の候補再生は喪失なし・TRACKING中の±1800deg/s飽和0だが、13881の仮想操舵最大は1156→1218deg/sへ増えた。

方位上限0.02deg/1msを適用したgainで共分散も更新し、O0/O2の各2万周期、各1000時点の正規化共分散固有値、位置/方位/bias上限・マーカー時の方位0を確認した。動画の機体表面から独立方位を測る方法は、基準自己対応以外14枚で特徴点不足となったため不採用。速度方向や外形PCAを真の機体方位へ読み替えていない。

これは固定した保存運動の近似再生で、実機で操舵を変えた閉ループの改善を保証しない。13881は選定用、過去3動画は既に見た診断データの再利用である。PC専用コピー以外のCore、SD値、機体への書込みは今回変更していない。先に用意した白線地図版2も未書込みである。

## 実機用へ移す際の実装方針

- 4状態の位置・方位・gyro biasの推定を維持し、白線のheading gainも有効にする。白線位置gainは法線方向だけ、マーカーは接線方向の位置だけとし、マーカーによる方位/bias更新は行わない。
- PC実験の一時フィールドlastHeadingCorrectionRadをそのまま常設せず、pathFusionFilterCorrectから明示的な方位補正出力[rad]を返す。PathFusionFilterの保存状態とRAMを増やさない。
- 現在の任意のlineThetaGainも残す場合は、同じ白線残差からの追加勾配をheading gainへ合成し、実際に適用するgainでJoseph形の共分散を更新する。呼出し側だけで追加・飽和して共分散と不一致にしない。残差15mmのクリップと5ms→1msの1/5倍率を保持する。
- 位置0.2mm/1ms・方位0.02deg/1ms・bias±5deg/sの上限を維持する。alpha=0時の補正無効と、既存の追加勾配だけを指定する設定の扱いを明示し、未検証の挙動を黙って変更しない。
- メタデータのpathFusionEstimatorは3へ分ける。pathWhiteMapVersion=2、pathObservationPolicyVersion=1、取得版2/優先度3を維持し、CSV列・レコード長・IMUの元の角度/校正・SD保存値を変更しない。lineThetaGain=0が追加勾配OFFを意味し、EKFの方位観測は別に有効になることを説明する。
- 現在のSD値5/0を維持する。新データだけで最良だったalpha=10や、biasを凍結する候補を同時採用しない。

## 必要な確認

実Cの符号・上限・不正入力・共分散PSDに加え、alpha=0/1/5/10/100と追加勾配0/1/10/100/1000、マーカー、白線欠測/復帰を確認する。現在の5走の固定入力再生と、設定変更・キャッシュ・白線地図版2の回帰を確認し、Debug/Release/詳細ログ/計測ONをビルドする。実機像と区別した不変ELF・元ソースを保存する。

書込み前は停止状態と出力0を読み、走行後のRAMが保存済みであることを確認する。GDBの直接関数呼出しは使わない。新しいELFからRAM配置と期待Flashを作り、全Flash照合・停止起動確認後に実IRQ/取得周期と実走動画を検証する。初回の速度条件は明示し、実走前から高速完走や同条件10本を確認済みとはしない。

証跡は[PC比較報告](../analysis/path_acquisition_220117/heading_ekf/report.md)、同フォルダのvalidation.json・summary.json・unit_validation.json・comparison.png。再現入口はanalysis/script/probe_heading_ekf_220117.py、validate_heading_ekf_probe_220117.py、finalize_heading_probe_220117.py。これらはPC専用コピーを生成するため、現行Coreへの正式実装と混同しない。
