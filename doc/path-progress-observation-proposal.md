# マーカーを使わないPATH系の進み位置補正案

状態：設計時の検討記録。制御版30として実装済み。実装の仕様・検証・制約は[白線履歴による進捗補正](path-progress-correction.md)を正とする。実走行効果は未検証。

対象はPATH/SHORTCUT/PATH_CURVE/SHORTCUT_CURVEの自己位置推定。14084の原因候補である、実白線と推定位置・経路位相の不一致を扱う。ユーザー指定により、距離補正の基準からサイドマーカー・クロスライン等のマーカーイベントを除外する。既存コードの削除や走行開始・ゴール判定の変更まで依頼されたとは解釈しない。

## 現行コードで確認した点

- DISTANCEはcourseAnalysis.cのprocessCourseMarkerで、検出したマーカーと一次記録の距離を対応させ、Control_ApplyMarkerCorrection_p経由でencTotalOptimal等を更新する。
- PATH系はpathFollower.cで車輪距離とジャイロからpathPoseを伝播し、最近傍の経路点から操舵・速度を決める。pathTravelMmは進みすぎた経路との誤対応を防ぐ上限にも使う。
- 白線観測は一次自身の前方センサー観測から作ったwhiteRouteと照合する。車軸の経路lineRouteと白線観測地図は別の基準点を表す。
- pathFusion.cのpathFusionFilterUpdateは、位置gainを白線の法線へ投影する。単一白線との共分散相関だけで接線方向の位相を動かさないための制限である。
- 過去にこの制限がない融合を1msへ移植した際、位相が先行し7本とも照合不能停止した。現在の制限を単に解除する方法は採らない。詳細はdoc/失敗事例/2026-10-27-path-white-observation-reference.md。

## 補正に使う基準

一次白線地図の**曲率が変化する形状**を基準とし、走行中に観測した白線の履歴を連続して照合する。直線からカーブへの接続、曲率の変化、左右の切返しなどを、一点のイベント検出ではなく一定距離幅の形状として扱う。

ジャイロと車輪距離は観測履歴を相対配置するために使い、白線センサーの実観測を地図との照合情報にする。実角速度と計画角速度だけを一致させても、経路制御自身が計画角速度を作っているため、実位置が正しい根拠にはならない。

直線では進行方向のずれを白線だけから識別できない。同じ形状が続く一定Rの円弧も、位置と方位を同時に未知とすると位相が曖昧になり得る。一定距離ごとに必ず補正する方式にはせず、形状から一意に識別できた時だけ補正する。

## 提案する処理

1. 新鮮で単一群の有効な白線観測だけを、相対移動・相対方位とともに短い履歴へ保持する。前方距離約95mmと各素子の横・前後位置を観測モデルへ含める。
2. 予測した経路位相の近傍に候補を限定し、履歴の白線点と一次白線地図の連続形状を照合する。グローバルな経路全体探索や周回間の飛び移りは許可しない。
3. 進み位置のずれ、横位置のずれ、方位ずれを分離して評価する。進み位置だけを動かして方位・横偏差を代わりに吸収させない。
4. 最良候補の絶対残差、他候補との差、進み位置を識別できる形状変化、履歴の被覆率、複数回の推定一致を満たした場合だけ受理する。曖昧・欠測・複数白線では補正を保留する。
5. 受理した位相差を上限付きで滑らかに反映する。制御用の経路進捗、pathPose、経路候補の進捗上限、速度・曲率の参照位置の整合を保つ。最近傍indexやencTotalOptimalだけを単独で変更しない。

車輪の生積算距離とCSVの生XYは補正しない。推定経路上の進み位置を別に管理し、実計測と推定補正を区別する。具体的な状態の持ち方と適用方法はホスト検証で決める。

ショートカット区間では一次の車軸軌跡と走行経路の距離が異なる。両経路の対応を保ち、白線へ戻す制御を短縮区間へ混入させない。初期検証では短縮区間と保護域で新補正を保留する。有効観測と一意な対応がない区間を無理に補間して補正しない。

距離に沿って履歴を標本化し、照合の計算回数・探索候補・履歴長を固定上限へ制限する。取得と補正適用は1ms制御に整合させ、重い探索を毎1msへ無条件に追加しない。具体的な実行周期とRAM量は実装時に測定して決める。

## 採用前の確認

- 合成入力：既知の前後ずれを与えた曲率遷移で補正の符号と量を確認する。横偏差のみ・方位誤差のみで偽の距離補正をしないことも確認する。
- 曖昧性：直線、一定R、繰返しS字、交差・複数白線、欠測、センサー更新停止では誤補正せず保留する。
- 実ログ：14083/14084と14080/14081/14082を、参照一次・速度設定の違いを保持して評価する。記録済みoptimalIndexを正解として与えず、推定器自身の進捗と最近傍選択で検証する。
- 記録運動の再生は、補正によって操舵した後の実機挙動を再現しない。残差改善だけで完走効果や物理位置精度を達成済みとしない。
- 補正前後の推定進捗・補正量・候補差・保留理由を診断可能にする。ログ追加が必要なら形式とAGENTS.mdを同時更新する。
- 実装を走行へ接続する前に、Debug/Release、補正上限・誤対応拒否・モード切替・割込み競合を確認する。実機では最長TIM6時間、センサー取得欠落、同条件10走以上の再現性を確認する。速度・ゲインは同時に変更しない。

今回の14084は自己位置ずれと整合するが、距離方向のずれが主成分だったか、横位置／方位のずれが主成分だったかは未確定。この案は、前後方向を補正できる観測を追加するものであり、距離補正だけで全ての自己位置誤差が解決するとは扱わない。
