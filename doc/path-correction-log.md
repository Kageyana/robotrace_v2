# 白線・マーカー補正ログの分離（2026-11-01）

PATH/SHORTCUT/PATH_CURVEで、白線の適用有無・位置量・方位量と、マーカーの適用有無・位置量を別々に保存する。列・単位・区間の定義は[自己記述ログ](self-describing-log.md#2026-11-01-白線マーカー補正の分離記録)を参照。

変更ファイルはpathFollower.c/h（補正寄与の区間集計）、log_schema.h（5列追加）、SDcard.c（ログ開始と保存成功時のクリア）、AGENTS.mdとログ仕様。制御演算、補正上限、センサー取得、割り込み呼出し順は維持する。集計とログスナップショット・成功時クリアは同じ1ms割り込み内で順次実行する。ログ開始時は走行前、経路無効化は既存の停止中処理を使い、新しい共有割り込み経路やSD書込は追加しない。

## ローカル確認結果

- `validation/path_correction_log/run.py`：実pathFollower.c/pathFusion.c/pathObservation.cと、SDcard.cから抽出した実ログキュー・writeLogBufferPutsを使用。HAL/SD入力と追加5列以外の保存値は模擬。通常/詳細×O0/O2・Wall/Wextra/Werrorの4組で成功。
- 白線単独、マーカー単独、同時成立と合成0.2mm上限、方位だけの白線補正、無効設定、欠測、SHORTCUT保護域、再走行/無効化時リセットを確認。区間内の複数補正の加算・未記録周期の保持・マーカーイベント重複抑止を確認。
- 実writerで記録無効・解析中・件数上限・書込失敗・バッファ不足時の保持、バッファ境界をまたぐ保存成功時のクリア、経路モード以外の0出力を確認。
- 各プロファイルの合成4行のヘッダ・全データ・スキーマ・メタデータCRCと、別実装による全5値の復号一致を確認。旧列の名前・型・式・順序が同じことを検査。
- 変更前と変更後を同じ最適化条件で実行し、100周期の保存制御トレースが全バイト一致。既存の経路生成・欠測・キャッシュ・3方式一致・回復/停止・短縮保護試験も成功。timer.c、pathFusion.c、pathObservation.c、emergencyStop.c、control.cは変更前と全バイト一致。
- `validation/path_correction_log/build.py before/after`：Debug、Release、DebugMarker、ReleaseDetailedCheckの全4構成を変更前後とも全体ビルド。既存6種の警告は同じで、新規警告なし。通常61列/168 B、詳細67列/177 B。
