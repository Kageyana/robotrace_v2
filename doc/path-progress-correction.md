# 白線履歴による経路進捗補正（制御版30）

PATH/SHORTCUT/PATH_CURVE/SHORTCUT_CURVEへ、マーカーイベントを使わない前後位置補正を追加した。白線の瞬時法線補正では識別できない前後ずれを、一定距離幅の白線形状が識別できた場合だけ補正する。速度表、PIDゲイン、FF、緊急停止閾値は変更していない。

## 観測と照合

`pathProgress.c`は生車輪距離と実ジャイロから、位置補正を含まない相対オドメトリを別に積分する。ラインセンサーの実取付位置を使って得た観測点を、異なる取得世代かつ15mm以上進んだ時だけ保持する。静的な20点の履歴を使い、最小220mmの幅・最古400ms以内を要求する。地図は現行`whiteRoute`で、前方センサー観測の地図を車軸経路へ置き換えない。

20ms以上の間隔で履歴を固定コピーする。前後変位-30/0/+30mmの3候補それぞれで、白線点と近傍地図線分の法線残差を評価する。各観測の探索は予測位相±5点に限定し、線分の両端が有効な場合だけ使う。線分外への投影は拒否し、地図端点による偽の接線情報を作らない。

前後位置・横位置・方位の3変数を同時に推定し、横位置や方位誤差を前後補正へ取り違えないようにする。最小二乗の情報行列から横・方位を分離した前後方向の情報量を検査する。直線・一定Rの円弧等の特異形状は受理しない。最終RMSは2.5mm以内、各残差8mm以内、前後差60mm未満、横差35mm以内、方位差8deg以内を要求する。別の解が前後8mm以上離れて同程度の残差なら曖昧として棄却する。

1候補4反復、3候補の計12反復を、1反復ずつ1ms周期へ分散する。1周期の線分検査は最大20×11=220回。動的メモリ、SDアクセス、待機処理、表示処理は追加しない。探索が有界であることと1msの実時間余裕は別であり、実機の最長時間は未確認。

## 補正の適用

別時点の照合で補正先が前後6mm以内・方位2deg以内で一致した場合だけ受理する。履歴は重なるため、統計的に独立な観測として数えない。受理した変換を相対オドメトリから現在時刻へ伝播し、現在の推定位置との差のうち経路接線方向だけを適用する。照合中の移動や既に適用した補正を再度加算しない。横・方位の推定値は照合の分離と検査に使用し、新処理から直接適用しない。

補正先は60msで失効、2mm以内の差は保留、1msの前後補正上限は0.1mm。既存の法線補正を先に適用し、残りの予算だけを前後補正へ使い、合計0.2mm/1ms以内を守る。`pathPose`と`pathTravelMm`を同量更新する。最近傍点・速度・FFの参照は、この補正を反映した既存の位置探索から継続する。生車輪積算、`encTotalOptimal`、生のCSV x/yを新補正で書き換えない。

`lineAlpha_x1000>0`の経路追従・注意状態で動作する。白線取得の鮮度・単一群の有効性を要求し、同一世代を繰り返し履歴へ入れない。白線不明瞭や鮮度切れでは補正先を直ちに破棄し、10ms続くと履歴も破棄する。滑りフラグON、短縮区間と保護域、クロス直線域、退避・再合流では履歴と補正先を破棄する。観測履歴の区間内に保護域がある場合も照合を開始しない。

PATH系の既存マーカー自己位置補正は呼出しと実装を除去した。開始・ゴールのマーカー判定、DISTANCEのマーカー距離補正、一次地図の従来生成処理は維持する。新処理の照合候補・補正量をマーカーイベントから生成しない。

## 設定とログ

調整定数と単位は`pathProgress.h`へ集約した。新しいSD設定やUI項目は追加していない。既存Line alpha表示0.000で既存EKFと新補正を無効にできる。

`routeControllerVersion=30`、`pathProgressPolicyVersion=1`で識別する。PATH系からslip診断9列29Bを除外し、前後補正の時系列12列34Bを末尾に保存する。通常67列/184B・詳細73列/193Bとなる。一次/DISTANCE/SLIPはslip列を含め通常65列/168B・詳細71列/177Bを維持する。残す列の順序・型・値、CRC形式、距離5mmの保存間隔は維持する。列位置が変わるため、解析は列名で参照する。

除外対象は`slipV2LongFast`、`slipV2LongSlow`、`slipV2Lat`、`slipV2YawDps`、`slipV2Flags`、`slipV2CurrentHighSamples`、`slipV2PwmSum`、`imuYawAlphaFiltered`、`imuLatTangentialApplied`。対象モードはPATH/SHORTCUT/PATH_CURVE/SHORTCUT_CURVEのすべて。スリップ検出の計算、補正の保留判定、設定メタデータは変更しない。

| ヘッダ | 意味 |
|---|---|
| pathProgressApplied_mm | 実際に適用した前後補正の符号付き累積[mm]。正は経路前方 |
| pathProgressAccepted | 別時点の照合が一致して補正先を受理した件数。補正量0の受理も含む |
| pathProgressReasonAtEnd | 最後の処理状態。下表を参照 |

| 状態 | 意味 |
|---:|---|
| 0 | 無効設定・滑り・保護域・追従以外等で停止 |
| 1 | 有効な履歴を収集中 |
| 2 | 履歴照合を実行中 |
| 3 | 前後位置を識別できない形状 |
| 4 | 地図との有効な線分対応がない |
| 5 | 残差・位置差・方位差の範囲外 |
| 6 | 近い残差の別解がある |
| 7 | 別時点の照合との一致確認待ち |
| 8 | 補正先を受理 |
| 9 | 有効・新鮮な白線観測がない |

## SDに保存する時系列診断

ヘッダの走行集計に加え、以下をPATH系の各レコードに保存する。SDは自己記述bin形式であり、列名・型・書式も保存される。

| 列 | 型 | 意味 |
|---|---|---|
| pathProgressDelta_mm | F32 | 前回保存成功以降の、実適用した符号付き前後補正量[mm] |
| pathProgressAbsDelta_mm | F32 | 同区間の実適用量の絶対値の和[mm] |
| pathProgressTotal_mm | F32 | 走行開始からの実適用量の符号付き累積[mm] |
| pathProgressAlong_mm | F32 | 数値評価できた最新の候補の推定前後差[mm]。適用量とは異なる |
| pathProgressRms_mm | F32 | 同候補の法線残差RMS[mm] |
| pathProgressInformation | F32 | 横・方位を分離した前後方向の情報量[無次元] |
| pathProgressReason | U8 | 最新の処理状態。前節の0〜9 |
| pathProgressReasonMask | U16 | 区間中に発生した状態集合。bit位置が状態番号 |
| pathProgressAcceptCount | U16 | 区間中に補正先を受理した件数。65535で飽和 |
| pathProgressRejectCount | U16 | 区間中に照合全体を棄却した件数。65535で飽和 |
| pathProgressMatchValid | U8 | 最新の照合が識別性・残差・別解検査を通過したら1 |
| pathProgressMatchAge_ms | U16 | 数値診断の最終更新からの時間[ms]。65535は未確定または飽和 |

前後量は正が経路前方。Delta/AbsDelta、受理/棄却件数、理由集合は保存成功時だけリセットし、保存失敗時は保持する。最新値と走行累積はリセットしない。理由集合には内部候補の処理状態も含み、短い棄却理由が記録間に消えるのを防ぐ。MatchValidは別時点の照合との一致確認や適用量非ゼロを表すフラグではない。候補値は数値評価できない場合に以前の値が残るため、Reason・MatchValid・MatchAgeを合わせて読む。

既存`pathWhiteCorrectionApplied/pathWhiteCorrection_mm`は法線と前後の白線補正を合成した各1msの位置補正を含む。新しいDelta列で前後成分を分離できる。`pathMarkerCorrectionApplied/pathMarkerCorrection_mm`は版30の経路モードでは常に0。RAMの走行集計は`pathProgressDiagnostics()`からも取得できる。

## 検証と限界

- `validation/path_progress/run.py`：製品CをO0/O2、-Wall/-Wextra/-Werrorで検証。直線・一定R・繰返し形状の拒否、前後±20mm、横のみ、方位のみ、混合誤差、保護域、地図欠測、無効設定、取得世代固定、白線消失、静止・非有限入力・リセットを検査する。前後±20mmは試験終端で-0.2/-0.9mmへ収束し、横のみは前後適用0、方位のみは0.2mmだった。合成条件での結果であり実機精度ではない。
- `validation/path_progress/integration.py --replay`：現行製品の生成・追従全体で、全4モード、マーカー非使用、既存の法線補正、合計200µm上限、保護域、欠測からの停止・復帰、モード切替を検証する。既存の白線EKFを維持したまま、新しい補正だけをON/OFFする。
- 14081/14082/14084をそれぞれ一次14080/14080/14083から再生成して固定入力再生し、O0/O2の出力一致と入力SHA不変を確認する。実ログの15速度項目を使用し、未記録のsearchはfixtureの1.0m/sとする。保存距離・積算角度を1msへ補間し、センサー・滑りフラグは保持している。実際の1ms取得鮮度、記録間のセンサー反応、スリップ診断の有効性は復元できない。
- この再生では14084の実停止7を再現できず、新補正OFFでも末尾まで喪失状態にならなかった。したがって14084のコースアウト改善、実位置精度、実機の閉ループ完走を証明する結果として使用しない。別条件の実走行を予測するものでもない。
- `validation/path_progress/metadata.py`：実writer補助と実ログ5本、O0/O2でヘッダ容量と末尾PID項目の保持を検査する。
- `validation/path_progress_log/run.py`：通常/詳細×新旧×O0/O2の56ログ4480行を、実writer/readerと独立復号で照合する。全CRC、PATHだけのslip9列除外、一次/DISTANCE/SLIPのバイナリ全体の一致、PATHの残す列と新診断値、保存失敗時の区間保持、XY補完による診断保持、旧PATH拒否・旧一次受入を検査する。直前のslipありPATH（213/222B）の28原本も別に保持し、除外9列以外の全値一致を確認する。実PC変換器はこの環境にないため未確認。
- 検証コード・実行ログはリポジトリ既定のvalidation/build領域へ保持する。最終ビルド・RAM・スタック・ソースSHAは`build/path-progress/final-validation.json`に保存する。

時系列追加後の一括検証はすべて成功。Debug/Release、ホストO0/O2、ARM GCCの-Wall/-Wextra/-Werrorを通過した。補正状態804Bとログ集計36Bの計840Bで、時系列追加前からの増分は40B。最大単一スタックフレームはDebug240B/Release264B。最新のソース・ELFのSHAと計測値は最終検証JSONへ保存した。単一フレーム値は割込みを含む最大スタック使用量ではない。既存の8KiBスタック予約は維持した。

実装完了時点では実機への書込み・実走行は未実施だった。その後、2026-11-03の実ログ14128で版30・一次14126・通常67列・前後診断12列・slip列除外を確認した。ユーザーは白線から外れて停止したと報告した。14121〜14125を含む診断付き6走で受理0回・実適用0mm。保存機能は確認できたが、新しい前後補正による実走改善は未確認であり、実コースで採用条件が成立しない問題が残る。詳細は[初回ログ解析](../analysis/path_progress_14120_14128/report.md)。最長TIM6時間とセンサー取得欠落、同条件10走以上の再現性、独立位置精度は未確認。一次地図自体の歪み、長い直線や一定Rで新しい基準を得られない制約も残る。
