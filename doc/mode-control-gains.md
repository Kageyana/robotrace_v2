# 走行モード別のPID・速度FFゲイン

速度PID、角速度FB付きライントレースPID、速度FFを以下の2組で管理する。

| UIのGrp | 共用する走行モード |
| --- | --- |
| BASE | 一次走行、PATH、SHORTCUT |
| CURVE | DISTANCE、SLIP、PATH_CURVE、SHORTCUT_CURVE |

SLIPは内部モードのDISTANCEとしてCURVEを使用する。SHORTCUTの短縮不成立時も要求された走行方式に従う。
角速度FBなしのラインPID（line.txt）とヨーレートPID（yawRate.txt）は共通のままとする。

## SD形式

既存ファイル名を使用し、改行なしのASCII整数を保存する。PIDの倍率とFFのCrr×1000、許容範囲0～255は従来どおり。

| ファイル | 保存順 |
| --- | --- |
| speed.txt | BASEのP,I,D,CURVEのP,I,D |
| lineomega.txt | BASEのP,I,D,CURVEのP,I,D |
| speed_ff.txt | BASEのFF,CURVEのFF |

各値は3桁ゼロ埋め。例: `012,000,004,010,000,000`、`150,160`。
旧形式の正常なPID3項目・FF1項目は、その値を両組へ引き継いで新形式へ更新する。
欠落ファイルは両組をコード既定値で作成する。部分的な破損では有効な項目を残し、欠落・範囲外だけ既定値にする。
open/read/closeのI/O異常は破損扱いの自動上書きをしない。書込は要求バイト数とclose結果を確認する。
旧ファームウェアは2組目を保持しないため、切り戻す場合は設定ファイルを退避してから行う。

## 手動調整

従来の角速度FBラインPID画面と速度PID画面を使う。
上下で項目を選び、左右で値を変更する。先頭の`Grp`で`BASE`または`CURVE`を選択する。
速度画面はGrp/P/I/D/FF、ライン画面はGrp/P/I/Dの順。
試験出力中は組と値の編集を行わない。

値を変更した操作で2組のRAM設定を保存する。SDが使用可能なら既存の3ファイルへ即時保存し、`SD`を表示する。
保存失敗は`ERR`、SDなしは`RAM`を表示する。SDなしでは電源断で変更が失われる。
手動走行・自動1走目の開始前にも両組を保存する。

## 制御への反映

走行開始前に実走行モードから組を選び、平均・左右輪の速度PID、角速度FBラインPID、速度FFを短い割り込み禁止区間で同時に反映する。
PRIMASKを元に戻す。前走の一時ゲイン復元先・曲率保持状態・積分状態をクリアし、同じ目標速度でもFFを再計算する。
走行中・ログ記録中は組を切り替えず、設定I/Oも行わない。1ms内へSDや表示処理を追加しない。

既存の直線・クロスライン用P2/D0への一時切替条件は維持する。SD保存は常に設定用の2組から行い、一時切替値で上書きしない。
ログ形式は従来どおりで、速度PID・FFは選択組の実制御値、ラインPIDヘッダは保存時の値（一時切替を含む）を記録する。
ライン制御診断の使用ゲインと併せて確認する。

## 確認

`validation/mode_control_gains/run.py`は実Cの設定I/O・UI・反映・FF計算・一時ゲイン切替をホストで確認する。
Debug/Releaseの通常ビルドも実施する。
実機では異なる2組を設定して保存・再起動・手動選択・自動5走を確認し、各モードのログと追従を照合する。
実機の走行安定性と割り込み最長時間はホスト検証では確定しない。
