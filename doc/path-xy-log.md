# PATH系の停止後XYログ

PATH、SHORTCUT、PATH_CURVE、SHORTCUT_CURVEの通常走行ログ`.bin`へ、`pathPlanX_mm`、`pathPlanY_mm`（F32、mm）の2列を既存末尾へ追加する。各行の`optimalIndex`に対応する実際の使用計画点で、短縮・周期地図補正・ゴール延長も含む。既存`x/y`と他の既存列の位置・型・意味は維持する。付属CSVと`pathXYFlags`は記録しない。

ユーザー指定により一次XYの`pathPrimaryX_mm/pathPrimaryY_mm`を削除した。停止後に一次原本を開き直す処理、XYの再構成・20mm補間、専用静的配列`logPathPrimary[2000]`（16,000 B）も削除した。走行前の経路生成に必要な一次ログの全CRC検証・受入条件は維持する。

PATH形式は通常63列/177 B、詳細69列/186 B。一次/DISTANCE/SLIP形式は従来の通常64列/166 B、詳細70列/175 B。既存の行数と5mm記録間隔、制御・経路生成を変更しない。走行中は追加8 Bの予約欄に0を書き、停止後に計画XYだけを補完する。`pathXYVersion=2`で識別する。版1は一次XYも含む4列だった。

計画XYと既存`x/y`は等縮尺で重ねて比較できる。時刻ではなく経路点番号の対応なので、同じindexが続く行では同じ計画座標になる。記録に現れなかった計画点のために行を増やさない。既存`x/y`は生エンコーダと保存方位による推定値で、物理位置の実測ではない。

保存は、走行停止→キュー排出→最終書込・truncate・sync→tmpをclose→実計画の一致確認→同じtmpを再open→計画XYの補完→通常の全件読込・CRC確定→schema/metadata・ヘッダ書込→sync/close/renameの順。開始時の経路点数・一次番号・形状CRCを共有RAM上の実計画と照合する。停止後の保存は一次原本が無くても実行できる。

既存の共有I/O領域6KiBを更新バッファへ切り替え、完全なレコード単位（通常34行・6018 B、詳細33行・6138 B）で1回走査し、計画XY以外の全バイトを保ってまとめて書き戻す。逆行するoptimalIndexにも対応する。CRC確定用の全件再読込を維持する。

メイン処理・FatFsロック下だけで補完する。経路不一致・不正index・I/O失敗ではbinへ確定せず未確定tmpを保持し、保存失敗として自動走行を停止する。例外ハンドラからのPATH保存は追加処理を実行せず失敗とする。通常の緊急停止は保存対象に含む。

DebugのRAMは89,256 B、Releaseは89,328 B（128KiBの68.15%）。専用16,000 B配列がmapから消え、共有I/O領域6144 Bとスタック予約8192 Bが維持されていることを確認した。実機の最大スタック・ヒープ使用量は未計測。

検証入口は`validation/path_xy_columns/run.py`。通常/詳細×O0/O2で実writer/typed reader・全CRC・実endLogを確認する。削除前出力と比較し、削除した一次XYの2列以外の全スキーマ・全保存値の一致、既存x/y位置、非単調index・複数バッチ・ゴール延長の計画XY、6モード、一次原本欠落でも保存成功、経路/所有者/index/停止/例外ガード、各I/O失敗と不足を検証する。証跡は`build/path-xy-remove-primary/validation/validation.json`。

自己記述RLOG v2の通常のS/F32列として保存する。配備済みPC変換器が現在の環境に無いため、そのexeによる変換は未確認。初回実機ログで2列・既存XYの位置・値・全CRCと停止後の保存時間を確認する。過去ログ自体は変更しない。

一次XYを保持していた版1の高速化比較は`build/path-xy-write-fast/compare/validation.json`に残す。その4列形式のバイト一致試験を、現行2列形式の検証には使用しない。
