# ライン角速度目標の基準速度2.5m/s

## 変更の目的と範囲

高速直線でラインセンサー偏差に対する目標角速度が増大するのを抑えるため、角速度FB付きライン追従の共通処理`motorControlTraceOmegaFB()`で、センサー偏差に掛ける速度だけに上限を設ける。

```text
速度倍率 = clamp(encCurrentN, -基準速度のパルス値, +基準速度のパルス値)
センサー由来の目標角速度 = (sensorDiff × 速度倍率) >> 9
```

基準速度は`PIDcontrol.h`の`LINE_TRACE_OMEGA_REFERENCE_SPEED_MPS=2.5F`で調整する。SD設定対象ではない。
58019pulse/m・1ms周期では2.5m/sは145.0475pulse/msとなり、整数未満を切り捨てて±145pulse/msを使用する。145pulse/msは約2.499m/s、次の146pulse/msは約2.516m/sに相当する。
実測値が±145pulse/ms以内なら従来の整数演算と一致する。ゼロ・後退の符号を保持し、停止付近で速度による除算を行わない。

対象は一次・DISTANCE・SLIPの角速度FB付きライン追従と、PATH/SHORTCUT/PATH_CURVE/SHORTCUT_CURVEの退避・復帰用ライン追従である。直線・カーブの判定やゲイン組による適用分岐は設けない。
スタート直後・ゴール後の角速度FBなしのライン追従`motorControlTrace()`には適用しない。

## 維持する処理

- 実角速度は従来どおり`imuVal.gyro.z`をそのまま偏差計算へ使用する。ジャイロ側を速度で縮小しない。
- 制限したセンサー由来目標を既存の低速小RカーブFFへ渡す。曲率FF自体の速度計算・適用条件と±1200deg/sの既存目標制限は維持する。
- PATH系の経路追従角速度は従来どおり経路側で生成する。今回の制限はセンサー由来のライン追従側だけに適用する。
- BASE/CURVEのゲイン、PIDのP/I/D計算、左右輪目標と出力制限、速度指令、緊急停止、1ms周期は変更しない。
- ログの列・単位・保存形式は変更しない。既存`targetAngularvelo`へ実際にPIDへ渡した制限後目標を記録する。

1ms経路に追加するのはローカル変数と整数の上下限比較のみ。共有状態・SD処理・表示処理・動的メモリを追加しない。基準速度のパルス換算はコンパイル時定数である。

## 確認

以下のホスト検証数値は基準速度3.0m/s時点の記録であり、現行2.5m/sでの再検証結果ではない。現行値は通常ログのDebug/Releaseビルドで確認済み。

ホストで実Cの目標生成・PIDを使い、正逆の174/175pulse/ms境界、ゼロ、最大入力、左右対称のセンサー偏差、一定ジャイロに対するFBの強さ、未校正時の出力停止、既存カーブFF・目標制限を確認する。
基準速度以下の目標・PID出力は変更前と照合し、高速入力は同じセンサー値の基準速度入力と照合する。ゲイン2組の既存ホスト回帰と通常ログのDebug/Releaseも確認する。

実行入口はリポジトリルートの`validation/line_omega_reference_speed/run.py`。O0/O2それぞれ33,696出力点で、基準速度以下18,144点が変更前と完全一致、高速15,552点が変更前へ±174pulse/msを与えた結果と完全一致した。目標だけでなくP/D項・積分状態・最終出力を照合し、O0/O2間の全出力バイトも一致した。ジャイロに対するP項の感度が速度で弱まらないことを別に確認した。
ゲイン組分けの既存回帰もO0/O2で成功。結果は`build/line-omega-reference-speed-20261103/host-validation.json`と`mode-gains-result.json`へ保存する。validation/とbuild/は既存方針どおりGit管理対象外とする。

実機の発振解消、制御割り込み最長時間、2.5m/sを超えるカーブの旋回余裕は未確認。実装後最初の走行でログの目標・実角速度・左右輪制限・ライン偏差とカーブ移行を確認し、同じ一次・速度設定の10走以上で再現性を評価する。
