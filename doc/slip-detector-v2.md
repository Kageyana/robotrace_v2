# スリップ検出の新旧並行評価版

ブランチ: `codex/slip-detector-v2`。2026-10-12実装。既定はSHADOWであり、走行制御・次走計画・距離補正は従来の判定を使用する。速度KF、ライン融合、オンライン減速は含めない。

この文書の列数・サイズ・ビルド値は初回SHADOW実装時点の記録。後続の診断専用横接線補正候補では通常72列/183 B・詳細87列/220 B、検出器状態1640 Bへ拡張した。2026-10-13の[ログ整理](light-log-43-columns.md)から通常43列/108 B・詳細87列/220 Bとし、新診断29列は一時的に詳細専用になった。2026-10-14のユーザー指示で[通常72列へ復帰](log-72-restored.md)し、診断29列を通常・詳細の双方へ記録する。現行仕様・互換性・追加検証は[横接線補正候補](slip-lateral-candidate.md)を参照する。初回SHADOWの計算と制御への接続は維持している。

## 検出と入力

`slipDetection.c/.h`はHALに依存しない固定メモリの検出器。入力、内部状態、結果、記録区間統計を別の構造体で管理する。状態は1460 B、動的確保なし。1ms割り込み内で更新する。

前後・横加速度は静止重力基準を引く既存IMU APIから取得する。既存の旋回中心補正を再度掛けない。移動開始時のバイアス再設定と走行中のバイアス学習は行わない。

速度と加速度を同じ5ms移動平均に通し、縦残差を`(ΔvEnc−∫aForward dt)/T`で求める。Tは10/30ms。横は30ms平均の`aLateral−vEnc×ω`。旋回整合は30ms窓で、過去8msの左右車輪差と現在のジャイロを比較する。

保存済み経験モデルは`wheelDifference = 0.00104395494 + 0.11145811347×ω + 0.00717649365×v`（速度m/s、ω rad/s）。学習元13074～13083のモデルを固定し、左右差はL−R、CW正。実効幅は物理寸法ではない。X軸の方向・接線補正と物理スリップの識別は未確定。

加速度・ジャイロの追加時間補正定数は0。根拠未確定の時間差を補償したとは扱わない。現在は非0への変更を静的assertで拒否し、将来変更する際に整列処理とテストを追加する。

|判定|ON|OFF|継続時間|
|---|---:|---:|---|
|縦（初回の版2は両窓、現行の版3はFast単独）|10 m/s²|8 m/s²|ON 3ms / OFF 5ms|
|横|4.6 m/s²|3.8 m/s²|ON 3ms / OFF 5ms|
|旋回不整合|60 deg/s|45 deg/s|ON 3ms / OFF 5ms|

絶対値で判定し、符号付き残差も保存する。2026-10-14の版3は縦ON・OFFからSlow条件だけを外し、`slipLongPolicy=fast_only`を記録する。LongSlowの計算・ログと両窓の区間最大値は維持する。変更範囲と検証は[Fast単独判定比較](slip-long-fast-only.md)を参照。これらは比較開始用の固定値であり、実機採用済みの閾値ではない。0.1m/s未満、走行外、校正中、IMU通信/受信時刻異常、非有限、1ms時刻の不連続で窓を捨てる。復帰後は43サンプルで全窓が充填されるまで無効。

電流は校正完了後の新しい10ms取得から有効とする。取得更新番号が変わった場合だけ、0.60 A超の連続回数を増やす。20ms以上古い入力や非有限値は電流補助診断だけ無効にする。低電流・低PWMを新判定の解除条件にしない。通信成功はセンサー内部の新サンプル生成を保証しない。DRDY同期は未導入。

## 制御からの分離とログ

`ROBOTRACE_SLIP_DETECTOR`はCMakeの`SHADOW`（既定）/`LEGACY`。適用モードは存在しない。従来の`updateSlipDetection()`と距離補正、コース解析は変更していない。LEGACYでも診断列は存在し、新判定は無効理由1として出力する。

新診断19列を既存列の末尾へ追加する。通常62列・157 B、詳細77列・194 B。列名、単位、無効理由ビットはAGENTS.mdを正とする。瞬時残差に加えて区間最大値、ON時間、有効/全観測時間、無効理由ORを残し、5mmログ間の短いイベントを保持する。16bitカウンタは65535で飽和し、未観測期間は補間しない。

`writeLogBufferPuts()`は保存成功をboolで返す。区間統計の消費は成功時に1ms側で行い、保存失敗時には保持する。前景処理から新検出器の状態を変更しない。SD実書き込みは既存のメイン処理のまま。

メタデータに版、評価モード、窓、閾値、時間補正、旋回校正を保存する。旧通常108 B/詳細145 Bの列定義は`log_schema_legacy.h`に固定する。どちらの旧形式も現在のビルドプロファイルに関係なく読み込む。旧CSVの列は旧形式のままで、新列欠落を0の正常診断へ置換しない。

現行はビルドと同じプロファイルの新形式のみ受け付ける。未対応スキーマ、サイズ、CRC異常は拒否し、CSV確定前の元バイナリ削除を行わない。

## 既存ログの参考再生と実機確認

13074～13088の全15本を、線形補間した1ms入力で実検出器へ与え、有限値を確認した。これは非因果の参考再生であり、実際の1ms取得、通信成否、静止重力基準、電流/PWM取得時刻は再現できない。保存加速度へ追加の静止基準減算を行わず、電流/PWM補助診断は無効とした。残差・フラグ割合は`reference-validation.json`に保存し、物理スリップ率や採用根拠に使用しない。

実機では最初のログで新旧列、メタデータ、cntlog、区間統計、保存・復旧を確認する。続いて同方式・同程度の電圧で最低10本を比較し、残差、検出位置、再現性、完走率、速度追従、ラップタイムを評価する。制御への適用は別の変更として判断する。
