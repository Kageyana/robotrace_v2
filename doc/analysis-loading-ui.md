# 走行前解析のローディング表示

手動のLOG解析5モードと、オートスタート2走目以降の6モード（SLIPを含む）で、`Analyzing`・解析モード・ログ番号・円環アニメーション・経過時間を表示する。経過時間は`000:00`の分:秒で1秒単位、最大999分59秒。解析ごとに0へ戻す。SLIPは従来の段階名・読込行数も最下段へ表示する。

円環は[Single Element CSS Spinners](https://lukehaas.me/projects/css-loaders/)の上段左から2番目（load2）を参考に、白黒128×64画面へ伸縮する回転弧として実装した。24×24の40枚をROM 2880Bに保持し、実行時の形状計算を省く。2秒周期、50ms間隔で最大20fps。円環は100Bの部分DMA、経過時間・SLIP進捗は下端2ページ256Bの別DMAとする。進捗は最短200ms間隔、秒数は変化時に更新する。初回だけ全画面を送信する。ビットマップの生成入口はローカルの`validation/analysis_display/generate_ring.py`。

`analysisDisplay.c`が手動・自動の両画面を担当する。解析の開始・終了を呼出元で囲むため、正常終了、解析エラー、キャッシュ利用でも同じ表示寿命になる。LCDなし、表示OFF、走行中、ログ記録中は有効化しない。

## 解析処理への負荷

- 解析中だけ従来の連続OLED転送を停止する。連続転送は各ページのDMA完了割り込みで同期I2Cコマンドを3個送っていたため、解析中のこの繰返しを除く。
- SDの送受信DMA開始後の待ち時間を使い、メイン側で描画する。短縮候補探索は開始点ごと、新規交差検査は外側16点ごとと内側128点ごとに更新可否を確認する。
- 描画・転送を割り込み処理へ追加しない。更新間隔未満、I2C使用中、転送開始失敗では解析を継続し、画面を待たない。HAL_Delay、転送待機ループ、三角関数、浮動小数点の書式変換、動的確保を追加しない。
- 既存の1KiB単発DMAスナップショットを、部分矩形と連続転送中の1ページ（128B）にも共用する。解析開始時に最後の連続転送が残っていても、DMAは描画バッファを直接参照しない。専用画面バッファは増やさない。部分転送中の終了では、全画面DMAで列・ページ範囲を復元してから連続転送へ戻す。
- 解析終了時は呼出元が結果・カウントダウン画面を描き終えてから連続転送を再開する。単発DMAが残っていれば、その完了後に再開する。手動画面の同期転送も、単発・連続の両転送が停止している場合だけ行う。
- 解析式、生成計画、ログ形式、SD設定、走行中の1ms処理は変更しない。ポーリング判定・描画・DMAのCPU負荷そのものはゼロではなく、実機の総解析時間が延びないことは別途計測が必要。

## 確認

ローカル専用の`validation/analysis_display/run.py`で、実`analysisDisplay.c`、実フォント、実描画・DMA関数をO0/O2・Wall/Wextra/Werrorで検証する。現行入口は実起動時の表示条件、初回表示、秒更新、tick周回、表示OFF・走行中・記録中のガード、転送中のコピー保持、解析終了時の復帰、部分転送の範囲検査を確認する。100kHz相当の転送時間と連続する進捗変更を与える試験では2秒間に円環39コマ、転送量8KB未満を確認した。過去の未更新initLCD依存コードは、保存済み変更前ソースで無表示を再現する。現在の入口に旧`--core`/`--expect-old-tearing`オプションはない。これらはホスト模擬であり、実機で一定20fpsを保証する結果ではない。

Debug/Releaseの通常ログ構成をビルドし、変更前と新規警告を比較する。実機では同じSD・ログ・設定で変更前後を交互に複数回計測し、手動5モード・自動6モードの解析開始から成功/失敗表示までを確認する。特に長いSHORTCUT探索、SLIP段階表示、キャッシュ利用、解析エラーからの画面復帰を確認する。今回、実機表示と実機解析時間は未計測。
