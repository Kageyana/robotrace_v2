# 走行前解析のローディング表示

手動のLOG解析5モードと、オートスタート2走目以降の6モード（SLIPを含む）で、`Analyzing`・解析モード・ログ番号・円環アニメーション・経過時間を表示する。経過時間は`000:00`の分:秒で1秒単位、最大999分59秒。解析ごとに0へ戻す。SLIPは従来の段階名・読込行数も最下段へ表示する。

円環は[Single Element CSS Spinners](https://lukehaas.me/projects/css-loaders/)の上段左から2番目（load2）を参考に、白黒128×64画面へ伸縮する回転弧として実装した。24×24の16枚をROM 1152Bに保持し、実行時の形状計算を省く。2秒周期、最大5fps。秒数とSLIP段階は値が変わったときだけ再描画する。

`analysisDisplay.c`が手動・自動の両画面を担当する。解析の開始・終了を呼出元で囲むため、正常終了、解析エラー、キャッシュ利用でも同じ表示寿命になる。LCDなし、表示OFF、走行中、ログ記録中は有効化しない。

## 解析処理への負荷

- 解析中だけ従来の連続OLED転送を停止する。連続転送は各ページのDMA完了割り込みで同期I2Cコマンドを3個送っていたため、解析中のこの繰返しを除く。
- SDの送受信DMA開始後の待ち時間を使い、メイン側で描画する。CPUを使う短縮候補探索・新規交差検査でも外側の16点ごとに更新可否だけを確認する。
- 描画・転送を割り込み処理へ追加しない。更新間隔未満、I2C使用中、転送開始失敗では解析を継続し、画面を待たない。HAL_Delay、転送待機ループ、三角関数、浮動小数点の書式変換、動的確保を追加しない。
- 既存の1KiB単発DMAスナップショットを、連続転送中の1ページ（128B）の固定コピーにも共用する。解析開始時に最後の連続転送が残っていても、DMAは描画バッファを直接参照しない。追加RAMは不要。連続転送中だけページごとの128Bコピーが増え、解析中は従来どおり単発転送のみとなる。
- 解析終了時は呼出元が結果・カウントダウン画面を描き終えてから連続転送を再開する。単発DMAが残っていれば、その完了後に再開する。手動画面の同期転送も、単発・連続の両転送が停止している場合だけ行う。
- 解析式、生成計画、ログ形式、SD設定、走行中の1ms処理は変更しない。ポーリング判定・描画・DMAのCPU負荷そのものはゼロではなく、実機の総解析時間が延びないことは別途計測が必要。

## 確認

ローカル専用の`validation/analysis_display/run.py`で、実`analysisDisplay.c`、実フォント、実描画・DMA関数をO0/O2・Wall/Wextra/Werrorで検証する。最大5fps、無変更100万回の追加転送なし、秒境界、tick周回、表示OFF、転送中スキップ、開始失敗、スナップショット保持、転送停止中・コマンド送信中・データ送信中の解析終了と連続転送復帰を含む。連続転送の全8ページで解析開始時に実DMA参照範囲が変わらないこと、手動5モード・自動6モードの成功・0件・エラーで結果描画が再開より先になることも確認する。変更前のCoreを`--core <変更前Core> --expect-old-tearing`へ渡すと、両問題を検出する負例を実行できる。実バッファから作ったプレビューは`build/analysis-loading-ui/host/preview.gif`へ保存する。

Debug/Releaseの通常ログ構成をビルドし、変更前と新規警告を比較する。実機では同じSD・ログ・設定で変更前後を交互に複数回計測し、手動5モード・自動6モードの解析開始から成功/失敗表示までを確認する。特に長いSHORTCUT探索、SLIP段階表示、キャッシュ利用、解析エラーからの画面復帰を確認する。今回、実機表示と実機解析時間は未計測。
