# ショートカット候補探索の高速化

SHORTCUT/SHORTCUT_CURVEの候補生成から、採否が変わらないと証明できる重複処理を省く。制御版29、採用上限49.5mm、抽出上限80mm、反転2回以上、候補長300～800mm、端点方位差12度、保護・除外区間、全点の変位検査、新規交差の拒否は維持する。ログ・SD形式・1ms制御は変更しない。

## 省略する処理

1. 旋回反転の累積回数を一度だけ計算する。候補内の反転回数の上界を2点の差で取得し、必要回数へ届かない候補は角度・変位・距離計算の前に除く。上界は区間外から入る反転を最大1回余分に含み得るため、残った候補には従来の詳細検査をそのまま適用する。
2. 同じ始点の候補は短い順に探索する。保護・除外点を含んだ後の長い候補も必ずその点を含むため、その始点の探索を打ち切る。
3. 新規交差検査では、両線分とも端点が一次経路から変更されていない組を省く。この組は一次経路と同じ交差状態なので、新しい交差にならない。変更端点を含む組には従来の判定を適用する。

累積値は速度計画を作る前の`driveRoute[].speed_cms`へ一時保持し、追加RAM・動的確保・大きい作業配列を設けない。別名`corridorTurnChanges`は実装専用として`pathFollower.c`に置く。一次経路の曲率半径は変更しない。候補決定後、従来の速度生成または一次経路への復帰で一時値を上書きする。キャッシュから基準経路を再利用する場合も、反転の累積値は生成ごとに作り直す。

## 検証と時間の扱い

`validation/shortcut_speed/run.py`は、保存した変更前Coreと現行Coreから実候補生成・速度生成関数を抽出し、同じGCC・O0/O2・Wall/Wextra/Werror・同じ浮動小数点保存条件で実行する。assertの副作用に依存せず、常時有効なCHECKで入力件数と検査を保持する。

29入力×一次半径の利用2条件×3モード（レベル0、SHORTCUT、SHORTCUT_CURVE）×先行減速0/30/99mmの522計画で、座標・方位・速度・保護/除外印・採否・短縮量が変更前と全バイト一致した。O0/O2の出力も一致する。全候補窓で、累積値からの上界が実際の反転回数以上かつ余分は最大1回であること、一次半径が書き換わらないことも検査する。

入力には0/1点、最小長の前後、最大1800点、変位境界、蛇行・交差・混合形状と、実ログ14038/14045/14048のXYを共通処理で約20mm間隔にした点列を含む。実ログ由来の3入力は1698/1695/1695点。白線地図正規化・ゴール延長・bin/FatFs読込までを再現する試験とは区別する。速度設定・一次半径の値も試験用の共通条件で、当時の実機速度計画を再現した値ではない。

初回のPC計数付き比較では、全条件合計の候補評価が20,205,012回から6,348,216回、線分交差判定が55,832,220回から15,004,116回、平方根が353,518,785回から81,516,249回へ減少した。O2の候補生成・速度生成部分の合計CPU時間は約15.8秒から約4.2秒。実ログ由来3入力のSHORTCUT・一次半径有効・先行減速30mmでは、それぞれ約0.32秒から約0.04秒となった。

この時間は計数ラッパー付きのPC比較であり、STM32上の秒数や走行間の待ち時間ではない。SD読込・全CRC検証・白線地図生成の時間は今回の最適化対象外。実機の総解析時間と表示の連続性は、同じSD・一次ログ・設定で変更前後を比較して確認する。計画が変わらない最適化のため、方式・制御版・安全条件を変更しない。

検証結果と変更前ソースは`build/shortcut-analysis-speed/`へ保存する。Debug/Release通常構成のビルド、新規警告、RAM使用量も確認する。ローカル検証コードは既存方針に従いGit管理対象外。
