## 競合の防止

以前は、TIM3がHALのBUSY状態によってLED位相更新を省略していた。一方、物理PWMは継続するため、管理位相と物理位相がずれ得た。さらにDMA完了時に管理位相を読み直すため、開始時と異なる位相・バッファを処理できた。HALはユーザー完了コールバックより先にBUSYを解除するので、処理中のバッファ再利用も防げなかった。

現在はTIM3カウンタとCH3比較値でLED位相を更新し、マーカー電源も追従する。ADC開始時に位相、バッファ、左右GPIO、取得世代を固定し、DMA完了時には固定情報のみを参照する。`adcAcquisitionBusy`は開始直前からライン・マーカー処理完了まで保持する。解放直前にDMBでメモリアクセスを完了させる。待機による競合解消は行わない。

CC1は同一位相内にだけ設定し、次周期への剰余による持越しを廃止した。遅延したCC1はカウンタ・取得予定位置・更新/CC3境界フラグ・走査余裕を確認して破棄する。HALのTIM割込み処理はCC1を更新イベントより先に処理するため、境界フラグでも一周前の要求を排除する。HAL開始処理中にTIM6が割り込んで窓を越えた場合も、完了結果を無効化する。

スキップ・開始失敗・転送異常では取得世代を進める。マーカーと平均化の未完成ON/OFFペアは新しい取得世代で破棄する。完成済みペアは3ms以内だけ保持し、完成ペア2組で各位相2サンプル平均を作る。電源切替では別の電源世代を進め、完成済みペアも破棄する。作業配列はDMA完了側だけが扱い、TIM3から直接初期化しない。公開直前に電源世代を再確認する。

UIのセンサ/PIDテスト画面は毎ループ`powerLineSensors(1)`を呼ぶため、既にONの場合は要求・世代・平均化を変更しない。初期化時のOFF要求は、HALが有効化した保留CC1も必ず解除する。

ライン差分と正規化は非公開の配列で計算し、PRIMASKによる短い割込み禁止区間で完成した40 Bと更新番号を公開する。完成ペアの積算状態80 Bの確定にも短い電源世代確認区間を使う。最優先TIM6のPIDは公開処理を途中で割り込めず、更新前または更新後の全10センサーを読む。計算全体・DMA待ちを割込み禁止にしない。マーカーとVREFINTの公開にも短い世代確認区間を用いる。元のPRIMASKを復元する。

## タイミングと維持した仕様

- TIM3: 90MHz / 12 / 3750 = 2kHz。ON/OFF各約250us。
- 位相イベント処理からCC1まで120us（900tick）。割込み遅延があれば、同一位相内に収まる場合だけ遅延後から120usを設定する。
- ADC1: 11ch、ライン10chは15cycle、VREFINTは480cycle、22.5MHz、12bit。走査は計算上約34us。開始窓に`LS_ADC_SCAN_MARGIN_US=50`の余裕を設ける。物理波形・実走査時間は未測定。
- `LS_AVERAGE_SAMPLES=2`、OFF平均−ON平均、負差分は0、既存の丸め・正規化を維持する。
- 通常は250usごとに1取得、4取得で1公開となり、公開周期は従来どおり1ms。欠測では未完成ペアだけを破棄し、期限内の完成ペア2組から復帰する。1msに1ペアだけ成功する周期的欠測では約2ms公開となる。
- PID計算式・ゲイン・1ms制御周期、左右・GPIO極性、マーカー判定条件、ADCサンプリング設定、PWM設定、`.ioc`、割込み優先度は変更していない。
- 通常CSV・バイナリスキーマへ診断列を追加していない。

確認した回路ソースはメイン基板・ラインセンサ・サイドマーカーの`.kicad_sch`、ピン設定は`.ioc`とMSP。メインのTIM3_CH3、Sidemarker_pwr、左右入力ラベルとPB0/PC14/PC13/PB13のソース設定を照合した。リポジトリのラインLED部品表記は`SIR19-21C/TR8`で、依頼で示された実装部品`HIR19-21C/L11/TR8`と異なる。実機の3.3kΩ・HIRの条件を与件として維持し、CAD部品値や時定数を根拠に設定を変更していない。

## 診断値の確認

Debug ELFのデバッガで以下のグローバル変数をWatchする。走行前後の累積値の差で件数を評価する。初回実装時はSWD接続・実機計測を行っていない。後続の静止検証結果とGDB停止による観測影響は別紙に記載した。

| 変数 | 意味 |
|---|---|
| `adcSkippedCount` | 窓失効・占有・HAL/DMA競合などで破棄した取得機会数 |
| `adcStartErrorCount` | 実際にHAL開始を呼び、非HAL_OKが返った回数 |
| `adcLastStartStatus`, `adcLastErrorCode` | 最後の開始失敗のHAL戻り値、最後の開始/転送異常のADCエラーコード |
| `adcTransferErrorCount` | ADC1非同期エラーコールバックの回数 |
| `adcAcquisitionBusy`, `adcAcquisitionFault` | DMA/結果処理の占有、HAL異常による再取得禁止 |
| `lineSensorUpdateCount` | 差分・正規化10chを公開できた回数 |
| `lineSensorUpdateAgeMs` | 最後に更新番号の変化を観測してからの経過ms |
| `lineSensorMaxUpdateAgeMs` | TIM6で観測した最大更新間隔・停止継続時間。電源OFFを含めず、累積最大を保持 |
| `lineSensorUpdateStale`, `lineSensorStaleCount` | 操舵使用時の3ms以上未更新状態、その検出回数 |
| `lineSensorVrefSample` | 有効なDMA完了VREFINT（電源切替後未取得は0） |

更新間隔は1ms粒度のシーケンス監視であり、物理的な取得時刻の厳密測定ではない。平均更新周期は、電源ONで安定した一定観測区間の経過msを更新回数差で割って求められる。厳密なタイミングはGPIO波形/DWT等で別途確認する。

`LS_UPDATE_STALE_MS=3`は実機で調整可能な診断定数。電源OFF・有効な初回公開前は監視を待機し、PATH/SHORTCUTの経路操舵中は`lineSensorUpdateStale`を立てない。ラインへのフォールバック・再合流中はライン値を操舵に使用するため監視を有効にする。監視は既存`emcStop`へ接続しておらず、新しい強制停止は無効。将来の安全停止はこの診断フラグを明示的な有効設定と専用停止理由で接続し、別途検証する。

占有/HAL BUSY/DMA BUSY/ロックは待たずにスキップし、自動復帰する。実際の開始失敗と非同期HALエラーは、HALが失敗戻り値でも変換を開始する場合があるため、占有を解放したうえで`adcAcquisitionFault`を保持し、再起動まで再取得を禁止する。電源OFF→ONでこの異常ラッチを解除しない。異常ラッチをデバッガから強制解除すると、残留DMAの安全を保証できない。

## 実行確認

リポジトリ直下:

```powershell
python validation/line_sensor_adc/run.py
```

GCC C11、`-Wall -Wextra -Werror`、`-O0`と`-O2`の両方で成功。要求10ケースに加え、遅延CC1・境界フラグ・開始中の遅延・HAL/DMA/ロック競合・非同期エラー・PRIMASK復元を検証した。公開処理の全40バイトの各ストアでTIM6参照を試み、完成前の参照が延期されることを確認した。

変更前`c25677771e5b546f5755e78845c036b48d0f1ff8`の平均化・正規化を固定参照とし、4000取得/1000フレームでraw・正規化値が一致した。現在の実`motorControlTrace()`を両入力で実行し、PWMと積分値も一致した。通常時スキップ0、公開回数1000、1ms観測の最大更新間隔1ms。角速度FB側は同じ公開配列を使い、実装自体を変更していない。RAM校正の正常/異常完了も検証した。

初回実装時は`robotrace_v2/`でDebug/Releaseのconfigureとbuild成功。DebugはRAM 88056 B/FLASH 269568 B、ReleaseはRAM 88288 B/FLASH 176416 B。追加した取得処理にARM警告なし。既存の`getAngleSensor()`の未初期化index警告、および変更対象外の既存警告は残る。Debug/Release逆アセンブルで、正規化の除算は公開クリティカル区間の外、公開区間は比較・固定サイズ転送・更新番号操作だけであることを確認した。後続の完成ペア保持修正を含むビルド結果は更新停止修正の別紙に記載した。

既存ローカル`run_line_calibration_tests.ps1`から新検証を起動して成功。Cortex-MのIRQ命令をMinGWへ直接コンパイルする以前の方式は新しい公開保護処理に適さないため、実関数抽出とIRQモックへ接続した。`run_autostart_calibration_tests.py`も実行し、既存の自動校正・復帰・通常ラインPIDテストが成功した。ADC1/TIM3の生成初期化関数が作業開始コミットとバイト一致し、`.ioc`・MSP・IRQ・PID本体に変更がないことをスクリプトで確認した。

コンパイラとobjdumpは既知のDLL再配置問題の回避として承認された制限外環境で実行した。ソース・`.ioc`・HAL・PID・ログスキーマの差分も確認した。以上は実機接続前のPC検証結果であり、後続の静止検証は別紙に記載した。

## 実機で残る確認とリスク

1. 静止状態の全10ch・左右マーカー値、LED波形とADC開始/終了位置。
2. 通常/最悪負荷でのスキップ数、更新周期の平均・最大、TIM6実行時間、公開区間による割込み遅延。50usの走査余裕と3ms閾値の適否。
3. 低速・高速・カーブの追従、ライン偏差・角速度指令・制御応答と完走率の変更前比較。リポジトリ方針に従い最低10本の比較ログを採用判断に使う。
4. 長期間DMA完了が来ない場合は占有を勝手に解放せず、更新停止診断で検出する。HAL異常は再起動が必要。新しい強制停止が無効なので、異常時に最後の公開値が制御へ残る運用リスクを持つ。実測後に安全停止の有効化を別途判断する。

PCモックはADCアナログ応答や実ハードウェアの全割込みタイミングを証明しない。修正版とゲイン調整後の実機17走で完走を確認したが、ゲイン・方式・電圧が混在しており、最新PIDの同条件最低10本による安定性評価は未完了。
